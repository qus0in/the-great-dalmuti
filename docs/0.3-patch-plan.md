# 0.3 패치 계획과 “게임 가능” 기준

## 왜

“게임 가능”은 semver patch로 추적한다. API 자동 완주, 실제 Supabase API 완주, 브라우저에서 사람이 카드를 조작해 한 판을 끝내는 단계는 구분한다.

| 버전 | 담는 이슈/범위 | 상태 |
|---|---|---|
| 0.3.1 | PR #45의 첫 부분 패치 머지. #29는 머지 후 main 검증으로 종료, #33은 열림 유지 | 머지됨 |
| 0.3.2 | #33 실제 E2E 통과·런타임 수정, #35 저장 정책·모듈(`docs/storage.md`) | PR 열림 |
| 0.3.3 | #34 브라우저 카드 조작 흐름 | 계획 |

상태가 바뀌면 이 표를 갱신한다. 진행 상태는 이 semver 표로만 기록한다.

## 무엇을

### 게임 가능 단계

| 단계 | 확인 기준 | 검증 근거·전제 |
|---|---|---|
| A. 가짜 저장소 API | 4석 한 판을 HTTP API로 끝내고 순위·전적을 확인하는 자동 시나리오 | 자동 검증 근거: `src/ui/game-runtime-flow.test.js`, `src/ui/game-runtime-flow-single.test.js` |
| B. 실제 저장소 API | 테스트 전용 Anonymous 계정 4개로 실제 Supabase API 한 판을 끝내고 JWT·RLS·공개/비공개 경계를 확인한 뒤 계정을 삭제 | 충족: 익명 테스트 계정 4개, 멀티·단독 2게임 완주, 무토큰·위조 JWT 401, 31초 무행동 후 봇 대행 종료, 전적 모드 집계·대행 제외, REST·Realtime 손패 노출 0(로그인 사용자 관측 ≥1·누출 0, 미로그인 구독 0은 RLS 차단으로 정상), 계정·게임 삭제. 회귀: `src/app/game/runtime-progress-single.test.js`. 스키마: `docs/game-schema.md` |
| C. 브라우저 한 판 | 사람 1석이 브라우저에서 카드 조작으로 봇 3석과 함께 4인 한 판 완주 | 사용자 확정 기준: 사람 1석+봇 3석. #34 브라우저 흐름·Realtime·접근성 검증 |

“게임 가능” 중 사람의 브라우저 카드 조작으로 한 판을 끝내는 기준은 0.3.3에서 충족하도록 계획한다.

0.3.1은 첫 부분 패치로 PR #45에서 main에 머지했다. #29는 머지 후 main 검증으로 종료했고, #33은 0.3.2 실제 E2E가 완료 기준을 통과해 0.3.2 PR에서 닫는다. 각 PR은 해당 트리 차이의 전용 CI와 독립 리뷰를 거친다.

### PR #45 머지 결과

- PR #45는 `dev`→`main`으로 머지됐고 merge commit은 `398f8ad`다. Draft는 해제됐으며 별도 태그나 릴리스는 만들지 않았다.
- 머지된 본문은 닫는 이슈 없이 #29·#33을 참조한다. #29는 main 기준 검증(0.2 대비 화면 비교, 배포 OG 메타)으로 종료했고, #33은 0.3.2 실제 E2E 통과로 닫힘 예정이다.

### 이슈별 기준과 근거

- **#29**: 0.3.1 main 머지 후 검증으로 종료. 검증 기준: 0.2 대비 데스크톱·모바일 화면 비교(JS 비활성 정적 화면), 배포본 서빙 HTML의 OG·Twitter 메타 확인. 근거: `dist/index.html`, `dist/play.html`, `src/ui/public/index.html`, `src/ui/public/play.html`, 이슈 #29.
- **#33**: 실제 Supabase E2E 완료 기준 전체 통과(0.3.2 PR에서 닫힘 예정). 익명 테스트 계정 4개와 실제 JWT로 멀티·단독 2게임을 끝내고 전적 저장·조회, 봇·31초 대행, RLS와 공개/비공개 경계(손패 노출 0)를 확인한 뒤 계정·게임을 삭제. 자동 근거: `src/ui/game-runtime-flow.test.js`, `src/ui/game-runtime-flow-single.test.js`, `src/app/game/runtime-progress-single.test.js`, `src/infra/game/`, `docs/game-schema.md`, 이슈 #33.
- **#34**: querySelector 계열 DOM, 별도 ES 모듈, 카드 선택·내기·패스의 axios 호출, 브라우저 E2E. 기준 화면: `src/ui/public/play.html`, 이슈 #34.
- **#35**: 저장 항목·수명·키·금지 데이터 표, 100줄 이하 모듈과 테스트, 실제 사용·문서 일치 및 민감 정보 미저장 확인. 근거: `docs/storage.md`, `src/ui/public/js/storage.js`, `docs/adr/0004-0.3-session-and-stats.md`, 이슈 #35.

## 어떻게

- `docs/deployment.md`는 main 병합 뒤 Render 자동 배포를 설명한다. 이번 부분 패치 PR의 main 병합과 이에 따른 공개 배포는 사용자 승인 범위다.
- 각 PR 본문에는 해당 패치에서 완료 기준 전체를 통과한 이슈만 Closes #N으로 쓴다. 자동 API 통과만으로 실제 DB나 브라우저 완주를 주장하지 않는다.
