### 게임 가능 단계

| 단계 | 확인 기준 | 검증 근거·전제 |
|---|---|---|
| A. 가짜 저장소 API | 4석 한 판을 HTTP API로 끝내고 순위·전적을 확인하는 자동 시나리오 | 자동 검증 근거: `src/ui/game-runtime-flow.test.js`, `src/ui/game-runtime-flow-single.test.js` |
| B. 실제 저장소 API | 테스트 전용 Anonymous 계정 4개로 실제 Supabase API 한 판을 끝내고 JWT·RLS·공개/비공개 경계를 확인한 뒤 계정을 삭제 | 충족: 익명 테스트 계정 4개, 멀티·단독 2게임 완주, 무토큰·위조 JWT 401, 31초 무행동 후 봇 대행 종료, 전적 모드 집계·대행 제외, REST·Realtime 손패 노출 0(로그인 사용자 관측 ≥1·누출 0, 미로그인 구독 0은 RLS 차단으로 정상), 계정·게임 삭제. 회귀: `src/app/game/runtime-progress-single.test.js`. 스키마: `docs/game-schema.md` |
| C. 브라우저 한 판 | 사람 1석이 브라우저에서 카드 조작으로 봇 3석과 함께 4인 한 판 완주 | 충족: 브라우저 E2E 실제 Supabase 완주(axios 44건 200, 계정·게임 삭제). 사용자 확정 기준: 사람 1석+봇 3석. #34 브라우저 흐름·Realtime·접근성 검증 |

“게임 가능” 중 사람의 브라우저 카드 조작으로 한 판을 끝내는 기준은 0.3.3에서 충족했다(PR #47 머지, 태그·릴리스 없음).

### PR #45 머지 결과

- PR #45는 `dev`→`main`으로 머지됐고 merge commit은 `398f8ad`다. Draft는 해제됐으며 별도 태그나 릴리스는 만들지 않았다.
- 머지된 본문은 닫는 이슈 없이 #29·#33을 참조한다. #29는 main 기준 검증(0.2 대비 화면 비교, 배포 OG 메타)으로 종료했고, #33은 0.3.2 실제 E2E 통과 후 PR #46에서 종료했다.

## 어떻게

- `docs/deployment.md`는 main 병합 뒤 Render 자동 배포를 설명한다. 이번 부분 패치 PR의 main 병합과 이에 따른 공개 배포는 사용자 승인 범위다.
- 각 PR 본문에는 해당 패치에서 완료 기준 전체를 통과한 이슈만 Closes #N으로 쓴다. 자동 API 통과만으로 실제 DB나 브라우저 완주를 주장하지 않는다.
