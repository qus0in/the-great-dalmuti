# 후반 결정과 사건 회고

## 상황 (Situation)

2026-10-16 후반, 0.2 계열 patch 경로를 열고 0.3 인증·UI를 진행하는 과정에서 결정 번복, 게이트 함정, 응대 문제, 문서 언어 혼입이 잇달아 드러났습니다. 하네스 장부에 남긴 사건들을 한데 모아, 각 사건이 바꾼 규칙과 그 위치를 함께 기록합니다.

## 과제 (Task)

다섯 사건을 되짚습니다: ① 브라우저 탑재 방식 결정 번복과 서버 인증 코드 보관, ② PR 충돌로 CI 미실행, ③ `/hall` 404 응대, ④ 0.2 계열 patch 경로 신설, ⑤ 한국어 문서 비한국어 혼입.

## 조치 (Action)

### 1. 브라우저 탑재 방식 결정 번복 (70 → CDN → 73a)

- 처음에는 "Express가 `node_modules`에서 supabase-js 브라우저 빌드를 서빙"으로 정했으나, 사용자가 CDN 방식으로 정정했고, 이어 설계 눈높이 기준(초반부 수강생 가정)에 따라 #30·#31은 브라우저 전용(CDN `supabase-js`), 서버 토큰 검증은 #33으로 미뤘습니다.
- 이미 만든 서버 인증 코드(`domain/auth`·`app/auth`·`infra/auth`)와 npm 설치분은 커밋하지 않고 보관(원복)했습니다.
- 반영: [ADR-0010](../adr/0010-0.3-browser-supabase-js.md) 확정 1·4, [AGENTS.md](../../AGENTS.md) 구조(0.3) 눈높이 1줄.

### 2. PR 충돌로 CI 미실행

- 0.2 스쿼시 머지 결과가 dev로 되돌아오지 않아 PR이 충돌 상태가 되었고, 충돌 PR은 CI가 아예 트리거되지 않아 검증 공백이 생겼습니다.
- 두 트리가 같은 것을 확인해 내용 변화 없이 해소했습니다.
- 반영(예정 포함): [git-flow 스킬](../../.agents/skills/git-flow/SKILL.md)에 ship 이후 dev 동기화 확인과 "충돌 PR은 CI가 뜨지 않는다"를 명시하는 단위가 이어집니다.

### 3. /hall 404 응대

- 사용자가 `/hall` 404를 보고했는데 "그 주소는 없다"며 사용자 입력을 먼저 탓했고, 사용자가 정정한 뒤에야 응대 문제를 인정했습니다.
- 교훈은 사실 판단이 아니라 태도입니다. 맞고 틀림과 무관하게, 사용자가 보고한 동작 실패는 먼저 우리 결함으로 받아 수정 단위나 제안으로 답하고, 사실 설명이 필요하면 해결안과 함께 둡니다.
- 반영: [orchestrate 스킬](../../.agents/skills/orchestrate/SKILL.md)에 사용자 보고 실패 응대 1줄.

### 4. 0.2 계열 patch 경로 신설 (62f)

- 단순한 CSS·HTML 수정으로 고칠 수 있는 감사 결함은 0.2 계열 patch로 내보내기로 하고, hotfix 브랜치 → `v0.2` 브랜치 PR → 태그 → dev 이식이라는 경로를 정했습니다.
- 반영: [ADR-0009](../adr/0009-0.x-learn-branches.md) 62f, [릴리스 0.2.1](../releases/0.2.1.md).

### 5. 한국어 문서 비한국어 혼입

- 한국어 ADR에 영어 동사와 일본어 문자가 섞여 리뷰 블로킹이 났고, 원인은 결정 장부의 영어 단어를 작성자가 그대로 옮긴 것이었습니다.
- 반영: [orchestrate 스킬](../../.agents/skills/orchestrate/SKILL.md)에 "한국어 문서로 이어지는 장부·브리프 인용은 한국어로, 한국어 문서 작성 브리프는 보고 전 비한국어 토큰 검사" 1줄.
