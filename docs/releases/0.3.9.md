# 릴리스 0.3.9 — 대기실 링크 복사 안내와 ADR-0017 미결 해소

## 개요

0.3.8(`de0ed70`) 이후 `dev`에 쌓인 작은 마무리를 묶은 패치로, 대기실에서 초대 링크를 복사했을 때 결과를 화면에 알리고(ADR-0017 결정 3), ADR-0017의 미결 3건을 전원 해소하며, 하네스 `set-effort`를 `agy` 1.4.2 인자형에 맞게 고친 릴리스입니다. 독자는 나중에 수업자료로 읽는 학습자를 가정합니다.

**실제 범위**: `main` 끝점(`de0ed70`) 이후 `dev` 변경 5건 — `1bfc554`(0.3.8 릴리스 문서), `e5a1b8f`(0.3.8 릴리스됨 표기·학습 브랜치 기록), `51dcbfa`(하네스 `set-effort` 보강), `50ea69c`(ADR-0017 미결 해소), `67fa5ab`(대기실 링크 복사 안내) — 만 포함합니다. 태그 대상은 0.3.9 끝점이며, 이후 별도 배포·이슈 작업은 포함되지 않습니다. 닫는 이슈는 없습니다.

## 상황 (Situation)

- 0.3.8에서 참가 코드 대기실이 열렸으나, '초대 링크 복사' 버튼을 눌러도 복사 성공 여부를 화면이 알려주지 않아 같은 방에 들어오는 길의 마무리가 빠져 있었습니다(ADR-0017 미결 1).
- ADR-0017에 미결 3건(링크 복사 안내·채팅 스택 수용·직접 API 신고 위험)이 남아 있었고, 그중 숨김 기간 쟁점은 0.3.8 출시로 상황이 끝났으나 문서에 반영되지 않았습니다.
- 하네스 `set-effort`가 `agy` 1.4.2의 인자형 `/model` 전송 방식과 어긋나 작업 `effort` 전환이 막힐 위험이 있었습니다.

## 과제 (Task)

- 대기실 링크 복사 결과를 성공·폴백 두 가지로 화면에 안내하고, 복사 로직을 별도 모듈로 분리합니다.
- 사용자 위임(2026-10-19 "아래 3가지 알아서 결정")에 따라 미결 2건을 오케스트레이터 결정으로 확정하고, 상황 종료 1건을 해소 항목으로 기록해 미결을 0건으로 만듭니다.
- `set-effort`가 `agy` 1.4.2 인자형으로 `effort`를 전환하게 고치고, 전후 모델·`effort` 검사를 유지합니다.

## 행동 (Action)

각 항목은 왜(why) -> 무엇(what) -> 어떻게(how) 순으로 설명합니다.

### 대기실 링크 복사 안내 (`67fa5ab`, ADR-0017 결정 3)

- Why: 링크 복사 버튼을 눌러도 화면이 아무 말을 하지 않으면, 방 만든 사람이 초대가 됐는지 알 수 없어 참가 코드 흐름의 끝이 끊겼습니다.
- What: 복사 성공 시 `"링크를 복사했어요."`, 클립보드 실패(텍스트 선택 폴백) 시 `"링크를 선택했어요. 직접 복사해 주세요."`를 대기실 링크 행 아래 `role="status"` 한 줄 영역에 안내합니다. 복사 로직은 `play-lobby-copy.js`로 분리했습니다.
- How: 클립보드 기록을 먼저 시도하고, 실패하면 텍스트 선택 폴백으로 이어지는 순서로 처리해 두 경로 모두 안내가 나가게 했습니다.

### ADR-0017 미결 해소 (`50ea69c`)

- Why: 미결이 남으면 다음 패치에서 같은 결정을 다시 물을 수밖에 없어, 위임받은 2건은 확정하고 상황 종료 1건은 기록으로 닫아야 했습니다.
- What: 링크 복사 안내·데스크톱 채팅 스택 수용·안내 문구 9개 확정을 결정 3–5로 확정하고, 숨김 기간 직접 API 신고 위험은 0.3.8 출시로 대응 대상이 사라진 해소 항목으로 기록해 미결을 없앴습니다.
- How: 사용자 위임 원문(2026-10-19 "아래 3가지 알아서 결정", "알아서 정리하기")을 이력에 남기고, 문구 9개는 ADR-0016 결정 15의 "사실만 짧게" 원칙과 0.3.8 E2E 통과를 근거로 원문 확정을 택했습니다.

### 하네스 `set-effort` 보강 (`51dcbfa`)

- Why: `agy` 1.4.2에서 `effort` 전환 방식이 바뀌어 기존 전송이 먹히지 않으면, 작업 강도 조절이 조용히 실패할 수 있었습니다.
- What: `/model <id>-<level>` 전송으로 `effort`를 전환하고, 잘못된 모델 응답 처리를 더했으며, 실행 전후 모델·`effort` 비교 검사를 유지했습니다.
- How: 인자형 전송 갈래를 `set-effort-agy.sh`에 두고, 라이브러리·실행 갈래 검사를 고쳐 회귀를 막았습니다.

### 0.3.8 릴리스 문서 동반 (`1bfc554`, `e5a1b8f`)

- Why: 0.3.8 문서와 표 갱신이 `dev`에만 있어 `main`에 함께 타야 0.3.9 태그 지점에서 추적 표와 릴리스 기록이 어긋나지 않았습니다.
- What: 릴리스 0.3.8 문서(기능 묶음 6개 정리)와 표의 "릴리스됨 (`v0.3.8`)" 표기, 학습 브랜치 `v0.3` 생성 기록을 같은 PR 흐름에 동반합니다. 새 기능이 아니라 기록 동기화입니다.
- How: 0.3 계열 첫 태그(`v0.3.8`)와 학습 브랜치 생성 사실을 문서에 고정하고, 0.3.9 표 행은 "작업 중"으로 둡니다.

## 결과 (Result)

- 5건 변경이 위 4묶음에 모두 근거로 등장하며, 패치별 절은 두지 않았습니다.
- ADR-0017 미결이 0건이 되었고, 대기실 링크 복사 안내가 `role="status"` 한 줄로 동작합니다.
- 남은 위험: 채팅 금지는 클라이언트 측 확인입니다(0.3.8에서 기록, 본 패치에서 변경 없음).
