# 릴리스 0.2.0 — HTML·CSS 프로토타입 화면 구성

## 개요

달무티(The Great Dalmuti) 온라인 웹 게임의 클라이언트 구현에 앞서 핵심 시각 디자인, 화면 레이아웃, 카드 표현 방식을 시각적으로 조기 검증하기 위해 HTML·CSS 프로토타입을 구축한 릴리스입니다. 서버 API나 복잡한 자바스크립트 로직 없이 순수 Semantic HTML과 모듈형 CSS만으로 대기실(Hall)과 4인 대전 플레이룸(Play) 화면을 완성했습니다.

**실제 범위**: 정적 시각 프로토타입(`dist/`), 디자인 시스템(`DESIGN.md`, CSS 토큰), 프로토타입 검증 스킬(`ui-prototype`), GitHub Pages 배포 설정만 포함합니다. 게임 로직, 인증, 서버 통신은 포함되지 않았습니다.

## 상황 (Situation)

- 카드 게임 규칙 구현 전 사용자 인터페이스의 사용성과 시각 계층 구조를 검증할 수 있는 신속하고 가벼운 프로토타입이 필요했습니다.
- 백엔드와 클라이언트 로직이 없는 상태에서 대기실과 4인 플레이룸의 화면 비율, 카드 부채꼴 배치, 상태별 시각 피드백을 브라우저에서 직접 확인할 환경이 요구되었습니다.

## 과제 (Task)

- 외부 대형 프레임워크나 복잡한 번들러 없이 순수 Semantic HTML과 모듈형 CSS만을 사용하여 100줄 코드 제한 규칙을 준수하고 실시간 배포가 가능한 환경을 완성합니다.
- 마일스톤 0.2.0(HTML·CSS 프로토타입 화면 구성)의 6개 이슈(#10, #11, #12, #13, #15, #17)를 처리하고 PR #25를 통해 `main` 브랜치에 병합합니다.

## 행동 (Action)

각 항목은 왜(why) -> 무엇(what) -> 어떻게(how) 순으로 설명합니다.

### 디자인 기반 및 토큰 체계 (#10, #13)

- Why: 계급 간 위계질서를 직관적으로 드러내고 일관된 스타일을 유지하기 위한 디자인 원천이 필요했습니다.
- What: ColorHunt 4색 기반 계급별 팔레트, 8px 그리드 간격, LevelUp / KotraGothic 타이포그래피, 고대비 접근성을 반영한 CSS 변수 토큰 및 기본 스타일을 구축했습니다 (`dist/css/tokens.css`, `dist/css/tokens/`, `dist/css/reset.css`, `dist/css/base/`).
- How: `DESIGN.md`에 디자인 원칙을 문서화하고, 비문서 코드 100줄 이하 분할 규칙에 따라 모듈형 CSS로 배치했습니다.

### 대기실(Hall) 화면 프로토타입 (#11)

- Why: 게임 입장 전 대기실 UI의 사용성과 계급 사다리 랭킹 표시를 검증해야 했습니다.
- What: 대기실 및 로비 셸 구조, 계급 사다리 랭킹 표시, 대기방 카드 그리드, 빠른 시작 및 방 만들기 인터랙션 목업을 제공합니다 (`dist/index.html`, `dist/css/hall/`).
- How: 공통 파운데이션의 버튼, 패널, 신분 배지 토큰을 일관되게 재사용하여 화면을 구성했습니다.

### 플레이(Play) 화면 프로토타입 (#12)

- Why: 4인 대전 테이블 아레나의 시각적 위계와 카드 인터랙션 배치를 사전에 검증할 필요가 있었습니다.
- What: 4인 테이블 아레나, 80장 수학적 카드 배분(남은 덱 0장, 중앙 필드 3장, 버린 패 20장, 4인 핸드 57장) 시각화, 세금 징수 완료 배너, 카드 상태 표현(선택, 낼 수 있음, 비활성화, 부채꼴 핸드 팬)을 구현했습니다 (`dist/play.html`, `dist/css/play/`, `dist/css/components/`).
- How: 순수 CSS 기법으로 12개 계급 및 어릿광대 카드, 카드 겹침 효과, 핸드 팬 배치를 구현했습니다.

### 프로토타입 배포 및 검증 스킬 체계 (#15, PR #25)

- Why: 프로토타입을 누구나 브라우저에서 체험하고 자동화된 도구로 품질을 검증해야 했습니다.
- What: GitHub Actions 기반 GitHub Pages 자동 배포 파이프라인(`.github/workflows/pages.yml`)과 `ui-prototype` 검증 스크립트(`check.sh`, `shot.sh`, `a11y.sh`)를 구축했습니다.
- How: PR #25를 통해 `dev`에서 `main` 브랜치로 통합했습니다.

## 결과 (Result)

- 마일스톤 0.2.0의 6개 이슈(#10, #11, #12, #13, #15, #17)가 모두 완료되었습니다.
- 깨끗한 모듈형 CSS 구조와 자동 검증 기준을 충족하는 반응형 HTML·CSS 프로토타입 화면을 완성했습니다.
- 한계점 및 향후 범위: 본 릴리스는 정적 시각 프로토타입이며, 인증 및 실시간 플레이는 정적 HTML + Express API + Supabase DB·Realtime 기반의 후속 마일스톤(0.3.0) 범위입니다.
