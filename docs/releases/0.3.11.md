# 릴리스 0.3.11 — 로그인 전 홈 화면 깜빡임 없애기

## 개요

0.3.10(`5353dd6`) 이후 `dev`에 쌓인 마무리를 묶은 패치로, 새 탭에서 대기실 화면이 먼저 보였다가 로그인 화면으로 바뀌는 흐름을 없애고, 세션이 있는 탭에서 로그인 화면이 먼저 보이는 흐름도 같은 방식으로 막은 릴리스입니다. 독자는 나중에 수업자료로 읽는 학습자를 가정합니다.

**실제 범위**: `main` 끝점(`5353dd6`) 이후 `dev` 변경 — PR #60(머지 커밋 `9b5ef97`) 1건만 포함합니다. 화면 4건(대기실·플레이·관리자·로그인), 공용 꾸러미 1건, 새 판단 모듈 1건, 기존 세션 모듈 고침 1건, 판단 함수 검증 1건, 추적 표 1행으로 총 9개 파일입니다. 닫는 이슈는 #59입니다.

## 상황 (Situation)

- 새 탭에서 홈(대기실)으로 들어가면 홈 화면이 먼저 보였다가 로그인 화면으로 바뀌었습니다. 세션 확인이 화면 렌더링과 외부 모듈 불러오기, 공개 설정 조회를 모두 마친 뒤에 일어났기 때문입니다. 세션 보관소가 탭별이라 새 탭마다 이 흐름을 겪었습니다(#59).
- 반대로 세션이 있는 탭에서 로그인 화면으로 가면 로그인 화면이 보였다가 대기실로 바뀌었습니다.

## 과제 (Task)

- 네 화면이 세션 확인을 마치기 전까지 본문을 가려, 상대 화면이 먼저 보이는 일을 막습니다.
- 복귀 주소·보호 화면·로그인 화면에 대한 판단을 순수 함수로 분리하고, 기존 세션 확인 흐름과 내보내기는 그대로 둡니다.

## 행동 (Action)

각 항목은 왜(why) -> 무엇(what) -> 어떻게(how) 순으로 설명합니다.

### 확인 전 본문 가림 (`9b5ef97`)

- Why: 화면은 토큰 확인보다 먼저 그려지므로, 확인이 끝나기 전에는 보이면 안 될 화면이 먼저 보입니다. 빈 화면 대신 목표 화면이 잠깐 보이는 쪽이 더 혼란하므로, 첫 페인트부터 본문을 가리는 편을 택했습니다.
- What: 네 화면(대기실·플레이·관리자·로그인)의 `body`에 `data-auth-guard` 걸림 표시를 둡니다. 첫 페인트부터 본문이 보이지 않고, 확인이 끝나 표시가 확정될 때만 가림을 풉니다.
- How: 가림 규칙은 네 화면이 공통으로 연결하는 기존 공용 꾸러미에 한 블록으로 두었습니다. 새 꾸러미 파일을 만들지 않으므로 연결 순서는 그대로입니다. 관련 파일은 `src/ui/public/index.html`, `src/ui/public/play.html`, `src/ui/public/admin.html`, `src/ui/public/login.html`의 `body` 표시, `src/ui/public/css/base/utilities.css`의 `body[data-auth-guard='pending']` 규칙입니다.

### 이동·표시 판단 나눔 (`9b5ef97`)

- Why: 가림을 푸는 시점과 이동할 화면을 한 덩어리로 처리하면, 복귀 주소에서 세션이 아직 없을 때 화면을 잘못 보내는 일이 생깁니다. 판단과 표시 동작을 나눠야 복귀 주소를 다르게 대할 수 있습니다.
- What: 판단 로직은 신규 `js/auth-gate.js`의 순수 함수로 뺍니다. 복귀 주소(`?code=`·`#access_token`) 가림, 화면·세션·복귀 여부에 따른 `to-login`·`to-home`·`show`·`wait` 결정, 표시 전환, 단추 연결, 가림 해제를 나눕니다. 기존 `js/auth.js`는 내보내기(`getClient`·`currentUser`·`signInWithGoogle`·`signOut`)를 유지한 채 `init`에서 판단 결과대로 이동·대기·표시합니다.
- How: 복귀 주소에서 세션이 없으면 가림을 유지한 채 세션 생성만 기다리고 로그인 화면으로 보내지 않습니다. 토큰 키는 있지만 무효인 경우 기존 확인 흐름이 로그인 화면으로 돌려보냅니다. 양쪽 모두 확인 뒤 이동이라 고리 이동은 없습니다. 관련 파일은 `src/ui/public/js/auth-gate.js`의 `isOAuthReturn`·`isProtectedPage`·`decideAuthGate`·`syncAuthUI`·`onAuthClick`·`revealAuthBody`, `src/ui/public/js/auth.js`의 `init`·`showApp`·`waitForSession`입니다.

### 회귀 검증 (`9b5ef97`)

- Why: 판단 결과 네 가지(`to-login`·`to-home`·`show`·`wait`)가 서로 뒤바뀌면 화면이 엉뚱한 곳으로 이동합니다. 판단 함수만 따로 떼어 검사해야 이동 규칙을 그대로 지킬 수 있습니다.
- What: 판단 함수 단위 검증 11건을 둡니다. 복귀 주소 3건이 `wait` 결정을 확인하고, 보호 화면 무세션 `to-login`, 로그인 화면 유세션 `to-home`, 유세션 보호 화면 `show`, 분류 확인을 다룹니다.
- How: 저장소를 직접 읽지 않고 기존 확인 흐름만 쓰는 순수 함수로 두었습니다. 관련 파일은 `src/ui/auth-gate.test.js`입니다.

### 추적 문서 (`9b5ef97`)

- Why: 0.3.11 범위가 추적 표에 남아 있어야 릴리스 기록과 진행 상태가 어긋나지 않습니다.
- What: 패치 표에 0.3.11 행을 두고 0.3.10 행은 손대지 않습니다.
- How: 관련 파일은 `docs/0.3-patch-plan.md`의 0.3.11 행입니다.

## 결과 (Result)

- 판단 함수 검증 11건과 화면 검사가 모두 통과했습니다.
- 세션 없는 탭에서 대기실·플레이·관리자 진입 시 보호 화면이 한 번도 보이지 않고 로그인 화면으로 갑니다. 세션이 있는 탭에서 로그인 화면으로 진입하면 로그인 화면이 보이지 않고 대기실로 갑니다.
- 복귀 주소(`?code=`·`#access_token`)에서는 즉시 로그인 화면으로 보내지 않고 세션 생성을 기다립니다.
- 남은 위험: OAuth 세션 교환이 실패하면 복귀 주소 탭은 가림을 유지한 채 세션 생성을 기다리므로 빈 화면이 남습니다. 이 경우는 0.3.14에서 처리할 예정입니다. 자바스크립트를 끈 탭에서도 가림 규칙 때문에 빈 화면이 남습니다(PR #60 본문).
