# ADR-0003: 0.3 전송과 저장

- 상태: accepted (채택·구현 머지됨, PR #45~#49)
- 날짜: 2026-10-15
- 관련: [ADR-0001](./0001-0.3-play-scope.md) (플레이 범위), [ADR-0002](./0002-0.3-rendering.md) (렌더링 방식), [ADR-0005](./0005-0.3-migration-boundaries.md) (이관 경계)
- 이력: [0.3 계획 프롬프트 로그](../prompt/2026-10-15-34-plan-0-3-ssr-express-supabase.md) (원문의 모듈 80줄 제한은 현재 100줄 제한이 대체), 닫힌 이슈 #30, #33, #34

## Why

사용자 최신 선택으로 Supabase DB + Realtime을 현행 전송·저장 방식으로 채택하고, 기존 SSE + Socket.IO 조합을 대체한다. 서버 권위와 비공개 손패 보호, 재시작 수명주기는 유지한다. 확정 외의 내용을 결정된 것으로 다루지 않는다.

## What

### 확정 결정

1. HTML 직접 작성과 Express API를 유지한다. 게임·봇·차례 규칙의 권위는 서버에 있다.
2. 내기/패스 포함 사용자 명령은 axios로 전송한다.
3. 방·비공개 손패·차례·완료 전적은 Supabase Postgres에 둔다.
4. 대기실·게임 알림과 presence는 Supabase Realtime으로 받는다.
5. 과거 경과: SSE 대기실 + Socket.IO 게임 조합을 한때 채택했으나 최신 선택으로 대체되었으며 현행 의존성이 아니다.
6. 브라우저 직접 구독에는 공개 URL/키와 단기 사용자 JWT를 사용하고, 비밀키는 서버에 둔다. 서버 전용 `.env` 정책은 비밀값과 의도적 공개 클라이언트 설정을 구분한다. 로그인은 브라우저 supabase-js로 수행하고 세션은 sessionStorage에 두며(탭별, [ADR-0004](./0004-0.3-session-and-stats.md)), axios는 `Authorization: Bearer`로 access JWT를 보내고 Express가 서버에서 검증하며 동일 JWT로 Realtime 구독을 인가한다.
7. Express 잔여 범위는 정적 서빙 + 서버 권위의 게임 규칙·봇·차례 판정 + 그를 호출하는 명령 API다. 인증·토큰 리프레시·JWT 검증·저장·RLS·Realtime/presence·전적 조회는 Supabase에 위임하며, 규칙은 RPC·Edge Function으로 옮기지 않고 클라이언트 판정도 하지 않는다(→ [ADR-0005](./0005-0.3-migration-boundaries.md) 이관 경계).
8. 토큰 갱신은 Supabase에게 위임한다: supabase-js 자동 리프레시, Express 검증은 Supabase 서버 클라이언트(`auth.getUser`/`getClaims`). 자체 JWKS/비밀 검증은 두지 않는다.
9. 재시작/배포 시 진행 판은 종료하고 복원하지 않는다. DB에 남은 옛 상태는 무효화·종료 표시 후 제공하며 자동 재개하지 않는다. 완료 전적·모드 분리·브라우저 세션·강제 퇴장 규칙은 유지된다.

### 제안 (공학적 수단, 사용자 명시 선택 아님)

- 부팅/epoch 무효화 또는 명시 종료 상태 부여.
- Supabase 장애 처리·클라이언트 재동기화·트랜잭션 + 멱등성 요구사항.

### 미결 사항

없음.

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| Supabase DB + Realtime(확정) | 저장·알림 일원화 | 벤더 결합 | 이관 경계와 병행 | 장애·재동기화 설계 |
| SSE + Socket.IO(대체됨) | 전송 직접 제어 | 저장 별도 필요 | 없음 | 현행 결정과 불일치 |
| SSE + axios(검토안) | 단순, 자동 재접속 | 양방향·저장 별도 설계 | 소규모 적합 | 현행 결정과 불일치 |

SSE + axios는 턴제 게임에도 가능한 검토안이었으며 기술적 불가능을 주장하지 않는다.

## How

- 렌더링은 [ADR-0002](./0002-0.3-rendering.md)에 따르며, 범위·재시작은 [ADR-0001](./0001-0.3-play-scope.md)에, 세션·전적은 [ADR-0004](./0004-0.3-session-and-stats.md)에 따른다. Express/Supabase 책임 분리는 본 문서 확정 7, 이관 경계는 [ADR-0005](./0005-0.3-migration-boundaries.md)를 정본으로 하며 중복 기록하지 않는다.
- 저장소·RLS·Realtime/presence 운영 등 현행 구현 상세가 필요하면 이 문서를 기준으로 하고, 전적 스키마·보존 기간은 [ADR-0004](./0004-0.3-session-and-stats.md) 확정 7–9에 따른다.
