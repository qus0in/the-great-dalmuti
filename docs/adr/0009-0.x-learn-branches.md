# ADR-0009: 0.x 학습 범위 브랜치

- 상태: accepted
- 날짜: 2026-10-16
- 관련: [릴리스 0.1.1](../releases/0.1.1.md)
- 출처: 사용자 결정 62 및 위임에 따른 오케스트레이터 결정 62a–62d (2026-10-16)

## Why

각 버전은 하나의 학습 범위를 의미하므로, 독자가 각 0.x 계열의 가장 최후 patch 상태를 브랜치로 열람할 수 있어야 한다. 태그는 불변이고 브랜치는 계열별 최신 patch를 가리키는 가변 포인터로 둔다.

## What

### 확정 결정

1. **결정 62 (사용자, 원문 그대로)**: "각각 버전은 학습 범위를 의미하므로 0.x의 가장 최후 patch 버전은 소스코드를 브랜치로 볼 수 있어야함".
2. **결정 62a (오케스트레이터 결정, 사용자 위임)**: 브랜치 이름은 `v0.<minor>` (`v0.1`, `v0.2`)로 하고 0.x 계열과 같은 이름 체계를 따른다. 태그는 `v0.x.y` 형식을 유지한다.
3. **결정 62b (오케스트레이터 결정, 사용자 위임)**: 브랜치는 해당 minor의 최신 patch 태그 커밋을 가리킨다. 2026-10-16 기준 `v0.1` → `v0.1.1` (`a36b45f`), `v0.2` → `v0.2.0` (`8372193`)이며 origin에 푸시되어 있다. 브랜치를 새로 생성하지 않고 기록만 한다.
4. **결정 62c (오케스트레이터 결정, 사용자 위임)**: 같은 minor의 새 patch 태그가 생기면 해당 브랜치를 fast-forward한다 (normal push, force 금지). fast-forward가 불가능하면 중단하고 사용자에게 질문한다. 해당 minor의 첫 태그가 생길 때 `v0.<minor>`를 만든다 (예: `v0.3.0` 시점에 `v0.3`).
5. **결정 62d (오케스트레이터 결정, 사용자 위임)**: 브랜치는 읽기 전용으로 직접 커밋하지 않는다. 수정은 `dev` → `main` → 새 patch 태그 경로로만 반영한다.

### 미결 (임의 결정 금지)

- 브랜치 보호 규칙(branch protection rule)은 미결이다. 사용자에게 제안 후 결정한다.

## How

- 본 ADR은 이미 origin에 존재하는 `v0.1`, `v0.2` 브랜치와 태그 `v0.1.1`, `v0.2.0`을 기록한다. 릴리스 문서는 [릴리스 0.1.1](../releases/0.1.1.md)을 참조한다.
- 이후 `v0.3.0` 등 새 minor의 첫 태그가 생기면 결정 62c에 따라 `v0.3` 브랜치를 만든다.
- 보호 규칙이 결정되면 본 ADR의 미결 항목을 같은 변경에서 옮긴다.
