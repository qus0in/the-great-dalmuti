# ADR-0002: 0.3 렌더링 방식

- 상태: draft (결정 채택, 인터뷰·리뷰 대기)
- 날짜: 2026-10-15
- 관련 이슈: [#19](https://github.com/qus0in/the-great-dalmuti/issues/19), [#20](https://github.com/qus0in/the-great-dalmuti/issues/20), [#22](https://github.com/qus0in/the-great-dalmuti/issues/22)
- 관련: [ADR-0001](./0001-0.3-play-scope.md) (플레이 범위), [ADR-0003](./0003-0.3-transport.md) (전송과 저장), [ADR-0005](./0005-0.3-migration-boundaries.md) (이관 경계)
- 이력: [0.3 계획 프롬프트 로그](../prompt/2026-10-15-34-plan-0-3-ssr-express-supabase.md) (원문의 모듈 80줄 제한은 현재 100줄 제한이 대체)

## Why

원래 0.3 계획은 Express SSR이었으나, 사용자가 HTML 직접 작성을 선택했다. 서버 주입 렌더링 대신 정적 HTML과 axios 조합으로 구현 기준을 고정하고, 기존 이슈와의 충돌을 명시한다. 확정 외의 내용을 결정된 것으로 다루지 않는다.

## What

### 확정 결정

사용자 선택(verbatim): 일단 html로 직접 작성하기 / 2번(정적 HTML + axios).

1. 마크업은 `.html` 파일로 직접 작성한다. EJS 등 서버 템플릿 엔진을 사용하지 않는다.
2. Express는 정적 HTML·에셋 서빙과 API를 담당한다. 서버가 데이터를 주입해 페이지를 렌더링하지 않는다.
3. 브라우저는 axios로 데이터·명령(내기/패스 포함)을 요청하고 querySelector 계열로 DOM을 갱신한다. JS는 별도 파일(ES modules)로 관리한다. 게임 알림·상태 수신은 [ADR-0003](./0003-0.3-transport.md)의 Supabase Realtime을 따른다.
4. 유지되는 제약: Supabase Google OAuth2 로그인, 서버 측 `.env` 사용, Render 배포(Dockerfile 없음), 클린 아키텍처(`ui` / `app` / `domain` / `infra`, 레이어 위에 피쳐), 코드 파일 100줄 상한, 프레임워크·번들러 미도입.

### 기존 이슈와의 충돌 (후속 정합 필요, 이슈 자체는 미변경)

- [#20](https://github.com/qus0in/the-great-dalmuti/issues/20)의 SSR 수락 기준은 본 결정과 충돌하므로 이슈 문구 정합이 후속 작업으로 필요하다.
- [#19](https://github.com/qus0in/the-great-dalmuti/issues/19)/[#22](https://github.com/qus0in/the-great-dalmuti/issues/22) 내 SSR 관련 조항도 동일하게 정합 대상이다.
- [#22](https://github.com/qus0in/the-great-dalmuti/issues/22)의 플레이 전송 서술은 [ADR-0003](./0003-0.3-transport.md)의 Supabase 전송·저장 결정으로 대체되므로 함께 정합 대상이다.

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| 정적 HTML + axios(확정) | 서버 단순, 0.2 산출물 재사용 | 첫paint 후 데이터 채움 | API 분리로 확장 | API·DOM 정합 부담 |
| 기존 Express SSR | 첫 응답 완성도 | 서버 렌더 부담 | SEO·초기 표시 | 템플릿·계층 복잡 |

## How

- API·세션 연동 상세 등 나머지 미결은 [ADR-0001](./0001-0.3-play-scope.md) 미결에 따르며 중복 기록하지 않는다.
- 이슈 문구 정합은 별도 후속 작업으로 진행하고, 본 문서에서는 이슈를 변경하지 않는다.
