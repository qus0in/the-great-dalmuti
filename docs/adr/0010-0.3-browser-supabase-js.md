# ADR-0010: 브라우저 supabase-js 탑재 방식

- 상태: accepted
- 날짜: 2026-10-16
- 관련: [ADR-0002](./0002-0.3-rendering.md) (프레임워크·번들러 미도입), [ADR-0003](./0003-0.3-transport.md) (브라우저 supabase-js 로그인)
- 출처: 사용자 선택 70 정정·70b·70c·73·73a (2026-10-16)

## Why

브라우저에서 `supabase-js`로 로그인해야 하는데 ([ADR-0003](./0003-0.3-transport.md) 확정 6), 번들러를 들이지 않고 ([ADR-0002](./0002-0.3-rendering.md)) 패키지를 싣는 방식이 정해지지 않았다. `docs/auth-google.md` 8절이 미결로 남긴 항목이다.

## What

### 확정 결정

1. **사용자 선택 70 정정 (원문 그대로, 2026-10-16)**: "supabase는 cdn" — 브라우저 `supabase-js`는 ESM CDN import로 싣는다. 앞의 "Express로 node_modules 제공" 선택을 대체한다.
2. **결정 70b (오케스트레이터 결정, 기본값)**: CDN은 jsDelivr `https://cdn.jsdelivr.net/npm/@supabase/supabase-js@<버전>/+esm`을 `<script type="module">`에서 import한다. 버전은 URL에 정확히 고정하고 서버 쪽 `package-lock`의 `@supabase/supabase-js` 버전과 맞춘다. 서버(`infra/auth`)는 계속 `npm` 의존성으로 `supabase-js`를 쓴다. 외부 CDN 가용성 의존은 감수한다. **결정 70d (오케스트레이터 결정)**: 현행 고정 버전은 `2.118.0`이며, 서버 `npm` 의존성은 #33에서 들어오므로 버전 일치 규칙은 그때부터 적용하고, 세션 저장소는 `window.sessionStorage`([ADR-0004](./0004-0.3-session-and-stats.md))로 한다.
3. **사용자 원문 70c (원문 그대로, 2026-10-16)**: "supabase는 브라우저에서는 cdn으로 하고, 서버가 나은 작업만 express에서" — 원칙: Supabase 사용은 브라우저(CDN `supabase-js`)가 기본이고, Express는 서버가 나은 작업만 맡는다 (비밀키가 필요한 작업·토큰 검증 같은 신뢰 경계). 서버 작업(예: `infra/auth` 토큰 검증)은 #33부터 도입한다 ([ADR-0003](./0003-0.3-transport.md) 확정 8).
4. **사용자 기준 73 (원문 그대로, 2026-10-16)**: "아직 서버를 모르는 수강생들에게 적절한 수준으로 고민. (아직 강의 초반부라고 가정)" — 이에 따른 **사용자 선택 73a**: #30·#31의 로그인·로그아웃·세션(`sessionStorage`, [ADR-0004](./0004-0.3-session-and-stats.md))·hall/play 진입 제어는 브라우저 CDN `supabase-js`로만 한다. Express는 정적 서빙과 기존 `GET /api/config`(공개 URL·publishable key)만 맡는다. 서버 토큰 검증은 #33에서 도입한다.

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| Express로 node_modules 제공 (기각 — 처음 선택했다가 사용자가 바꿈) | 외부 의존 없음 | 서빙 라우트 구현 부담 | 이후 Spring `WebJars` 방식과 유사 | 구현·유지 부담이 남음 |
| public/vendor 사본 커밋 (기각) | 외부 의존 없음 | 사본 관리 부담, 갱신 누락 | 검토 쉬움 | 저장소 비대·구버전 잔류 |

채택안(ESM CDN import)의 위협: 외부 CDN 가용성·무결성에 의존한다.

## How

- 서버 쪽 `npm` 의존성과 토큰 검증 도입은 #33 단위에서 한다.
- CDN import 적용은 로그인 화면 구현 단위에서 한다.
- 본 결정으로 `docs/auth-google.md` 8절의 미결이 해소된다.
