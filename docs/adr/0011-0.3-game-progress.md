# ADR-0011: 0.3 게임 진행: 상태 저장·Realtime·봇·전적

- 상태: accepted
- 날짜: 2026-10-16
- 관련: [ADR-0001](./0001-0.3-play-scope.md) (플레이 범위), [ADR-0003](./0003-0.3-transport.md) (전송과 저장), [ADR-0004](./0004-0.3-session-and-stats.md) (세션과 전적), [ADR-0006](./0006-0.3-tdd-bdd-and-layers.md) (레이어와 테스트), [ADR-0008](./0008-0.3-code-conventions.md) (검증·상태 코드), [ADR-0010](./0010-0.3-browser-supabase-js.md) (브라우저 supabase-js)
- 관련 이슈: [#33](https://github.com/qus0in/the-great-dalmuti/issues/33)
- 출처: 사용자 선택 86–91·95 (2026-10-16, #33 계획 질문)

## Why

#33(게임 진행 API와 Supabase 저장소) 착수 전에 계획 초안이 제시한 질문 4건에 사용자가 답했다. 구현이 시작되면 되돌리기 어려운 저장 형태·Realtime 노출·범위 결정을 먼저 고정한다. 설계 눈높이는 서버를 모르는 초반부 수강생(AGENTS.md Structure 0.3, [ADR-0010](./0010-0.3-browser-supabase-js.md))이라, 결정 근거가 설명 가능해야 한다.

## What

### 확정 결정

1. **진행 상태 저장 = 정규화 테이블 (사용자 선택 86)**: 게임·좌석·트릭·손패 등을 별도 테이블로 분리한다. 세부 스키마(테이블·칼럼 이름, 관계, 공개/비공개 구분)는 구현 단위에서 확정하며 본 ADR은 형태만 고정한다. 계획 초안이 추천했던 "게임 1행 + 상태 JSONB"는 기각되었다.
2. **Realtime = 공개 테이블 구독 (사용자 선택 87)**: 공개 필드만 담은 뷰/테이블의 행 변경을 브라우저 CDN `supabase-js`로 직접 구독한다([ADR-0003](./0003-0.3-transport.md) 확정 4·6). 손패 등 비공개 데이터는 어떤 브라우저에도 노출하지 않는다.
3. **봇·30초 타이머를 #33에 포함 (사용자 선택 88)**: 빈자리·싱글 봇과 30초 강제 퇴장·봇 대행은 [ADR-0001](./0001-0.3-play-scope.md) 확정 2·3·4·9의 실행부로, #33 범위에 포함한다.
4. **전적 저장을 #33에 포함 (사용자 선택 89)**: [ADR-0004](./0004-0.3-session-and-stats.md) 확정 2·7·8의 결과 행·집계 뷰·보관 규칙을 #33에서 구현한다.
5. **타이머 실행 위치 = 서버 프로세스 타이머 (사용자 선택 90)**: 30초 강제 퇴장·봇 대행 타이머는 Express 프로세스 안에서 관리한다. Supabase 스케줄·요청 시 지연 평가는 기각되었다.
6. **전적 읽기 API를 #33에 포함 (사용자 선택 91)**: 전적은 서버 API(예: `GET /api/stats`)로 조회한다. 브라우저가 Supabase를 직접 조회하는 안은 기각되었다.
7. **1라운드 = 한 판 (사용자 선택 95)**: 3명이 손패를 다 내면 순위를 확정하고 판을 종료하며 전적을 기록한다. 같은 방에서 다음 판을 이어 하면 이전 순위로 자리와 조공을 정한다. 정해진 라운드 수로 진행하는 안과 방장이 끝낼 때까지 이어가는 안은 기각되었다.

### 미결 (임의 결정 금지)

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| 정규화 테이블 (채택, 86) | 관계·RLS 단위 제어 명확, SQL 학습 소재로 설명 가능 | 테이블·조인 증가, 명령마다 다중 행 갱신 | 부분 갱신·질의 확장 | 규칙↔스키마 이중화 관리 부담 |
| 게임 1행 + JSONB (추천했으나 기각) | 구현·갱신 단순, 스키마 진화 자유 | 손패 노출 경계 관리 애매, 부분 제어·질의 어려움 | 초기 속도 | 학습 소재 약함 |
| 공개 테이블 구독 (채택, 87) | 서버 발행 코드 불필요(ADR-0003 확정 4·6 방향) | 공개 테이블 갱신 누락 위험 | 얇은 서버 유지 | 공개 필드 실수 노출 |
| 서버 Realtime broadcast (기각) | 노출 필드 완전 통제 | 서버가 Realtime API에 의존, 코드 증가 | — | 서버 복잡도 |
| 봇·타이머·전적 #33 포함 (채택, 88·89) | 완료 기준이 실제 4인 한 판에 근접 | #33 단위 수 증가 | 후속 통합 감소 | 단위당 10분 예산 관리 |
| 봇·타이머·전적 후속 분리 (추천했으나 기각) | 단위 크기·눈높이 유지 | 완료 기준이 부분 상태로 남음 | — | 통합 시점 지연 |
| 서버 프로세스 타이머 (채택, 90) | 단일 인스턴스·서버 권위·재시작 폐기와 정합 | 프로세스 소멸 시 타이머 소멸 | 구현 단순 | — |
| Supabase 스케줄·지연 평가 (기각) | 서버 독립 | 권위 판정이 저장소로 이동 / 무요청 시 멈춤 | — | 원칙 불일치 |
| 전적 읽기 서버 API (채택, 91) | 서버 경계에서 조회 통제, 클라이언트 단순 | API 1개 추가 | #34 배선 용이 | — |
| 브라우저 직접 조회 (기각) | 서버 코드 없음 | RLS·집계 노출 경계가 브라우저로 확장 | — | 비공개 원칙 약화 |

## How

- 세부 스키마·공개 테이블·API 경로 이름은 구현 단위에서 확정한다(계획 v2 초안은 제안이며 확정 아님).
- 검증·상태 코드·예외는 [ADR-0008](./0008-0.3-code-conventions.md) 결정 52·56, 레이어·테스트 방식은 [ADR-0006](./0006-0.3-tdd-bdd-and-layers.md), 서버 권위 판정과 저장 위임은 [ADR-0003](./0003-0.3-transport.md) 확정 7·8에 따른다 — 본 ADR에서 재기술하지 않는다.
- 브라우저 역할(CDN·세션)은 [ADR-0010](./0010-0.3-browser-supabase-js.md) 확정 4를 따른다.
