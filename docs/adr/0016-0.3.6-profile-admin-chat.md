# ADR-0016: 0.3.6–0.3.8 프로필 이미지·방 채팅·관리자 가리기·신고·이의제기

- 상태: accepted
- 날짜: 2026-10-18
- 관련: [ADR-0010](./0010-0.3-browser-supabase-js.md) (브라우저 우선·CDN `supabase-js`), [ADR-0004](./0004-0.3-session-and-stats.md) (세션), [ADR-0003](./0003-0.3-transport.md) (전송·Realtime)
- 관련 이슈: #41, #42, #43, #44
- 관련 이슈: 신고·이의제기 이슈(생성 예정)
- 출처: 2026-10-18 사용자 결정 (설계 인터뷰·후속 질답 35건)
- 이력: 결정 10 "승인. 남은 미결은 질답으로."(이슈 본문 수정·미결 처리), 결정 25 "현재 워커들에서 미리 처리할 수 있는 부분은 미리 착수"(진행 방식).

## Why

#44 설계 인터뷰와 후속 질답에서 0.3.6–0.3.8 패치의 프로필 이미지·방 채팅·관리자 가리기·신고·이의제기에 대한 사용자 결정 34건이 나왔다. #41–#44 구현을 시작하기 전에 저장 위치·형식·관리자 판별·가리기 범위·가린 원본 처리·화면 위치·채팅 범위·보관·제한·표시 방식과 신고 접수·자동 차단·운영자 차단, 이의제기·관리자 페이지·패치 분할을 한 문서에 고정해야 한다. 이 ADR은 사용자가 고른 결정만 확정으로 적고, 구현 수단과 아직 묻지 않은 항목을 분리한다. 기존 제약은 브라우저 우선([ADR-0010](./0010-0.3-browser-supabase-js.md)), 세션([ADR-0004](./0004-0.3-session-and-stats.md)), 전송([ADR-0003](./0003-0.3-transport.md))을 따른다.

   결정 27의 채팅 금지 해제 방식을 정하고, 미결 "신고 의심 차단의 채팅 금지 해제 방식이 사진 풀기와 같은지"를 해결한다.

### 제안 (공학적 수단, 사용자 명시 선택 아님)

- **버킷·경로 (작성자 제안)**: 공개 버킷 이름은 `avatars`, 객체 경로는 `<user_id>/avatar`로 두는 안. 버킷 설정은 허용 MIME `image/png,image/jpeg,image/webp`, 파일 용량 한도 `1MB`로 두고, 쓰기 정책은 `auth.uid()`가 경로 첫 조각과 같은 경우만 허용하는 안.
- **테이블 (작성자 제안)**: `public.admins (user_id uuid primary key references auth.users(id))`와 `public.hidden_profiles (user_id uuid primary key references auth.users(id), hidden_by uuid not null, hidden_at timestamptz not null default now(), kind text not null check (kind in ('suspected', 'violation')))`를 두는 안. `kind`가 의심·위반을 구분. 가리기 해제는 행 삭제로 처리. 두 테이블 읽기는 RLS·서버 조회로 제한.
- **업로드 차단 (작성자 제안)**: 결정 26의 업로드 차단은 `hidden_profiles`에 행이 있는 사용자에게 Storage INSERT를 거부하는 RLS 정책과, 브라우저의 업로드 버튼 비활성화·안내로 구현하는 안.
- **신고 테이블·자동 집계 (작성자 제안)**: `public.reports (reporter_id uuid not null references auth.users(id), target_id uuid not null references auth.users(id), reason text not null check (reason in ('photo', 'chat', 'other')), created_at timestamptz not null default now())`에 신고자-대상 유일 제약을 두는 안. 결정 28의 사유 3개를 코드 `photo`·`chat`·`other`로 둔다. 서로 다른 3명 집계 트리거가 `hidden_profiles`에 `kind='suspected'` 행을 넣는 안.
- **의심 원본 보존 (작성자 제안)**: 결정 23의 의심 보존은 원본을 비공개 버킷으로 옮겨 보존하고, 풀면 공개 버킷으로 되돌리는 방식으로 구현하는 안. 위반 확정 시 결정 9대로 삭제.
- **익명 계정 필터 (작성자 제안)**: 결정 13의 익명 계정 감추기는 `auth.users.is_anonymous`로 거르는 안.
- **이의제기 테이블 (작성자 제안)**: `public.appeals (user_id uuid not null references auth.users(id), hidden_at timestamptz not null, body text not null check (char_length(body) <= 500), status text not null default 'pending' check (status in ('pending', 'released', 'kept')), created_at timestamptz not null default now(), decided_by uuid references auth.users(id), decided_at timestamptz, primary key (user_id, hidden_at))`를 두는 안. `hidden_profiles.hidden_at`을 함께 저장해 차단 1건당 1회를 강제하고, 500자는 DB 제약으로 막는다. 결정 30의 풀기/유지 결과는 `status`로 남겨 본인 카드와 /admin 처리 기록에 보여 준다.
- **마이그레이션 (작성자 제안)**: 결정 34의 패치 순서에 맞춰 0.3.6 프로필 버킷·정책과 0.3.8 운영 테이블·정책을 각 패치의 마이그레이션 파일로 나누는 안. 기존 이름 규칙(`20261016163800_game_schema.sql`, `20261017062000_tutorial_mode.sql`)을 따름.
- **채팅 (작성자 제안)**: 기존 방 Realtime 채널에 `chat` 이벤트를 더해 `{ userId, name, text, at }`를 실시간 전송하고 DB 테이블은 만들지 않는 안. 길이·간격 제한과 수신 측 자르기는 확정 결정 7을 클라이언트에서 구현. 결정 19·27의 채팅 금지는 전송 전 차단 상태를 확인하고 수신 측도 차단된 사용자의 메시지를 표시하지 않는 안.
- **프로필 표시 (작성자 제안)**: 공개 URL은 `<user_id>/avatar` 경로로 만들고, `hidden_profiles`에 있으면 기본 아바타로 바꿔 표시하는 안. 결정 33의 기본 아바타는 사람 실루엣 SVG, 봇 아바타는 봇 SVG 1개씩으로 두는 안.
- **신고 UI (작성자 제안)**: 좌석 아바타와 채팅 메시지에 신고 버튼을 두고, 결정 28의 사유 3개를 고르는 작은 대화상자를 띄우는 안. 좌석에서는 '부적절한 사진', 채팅에서는 '욕설·도배 채팅'을 기본 선택으로 둔다.
- **이의제기 UI (작성자 제안)**: 가려진 본인의 프로필 카드에 '이의제기' 버튼과 500자 입력창을 두고, 제출 후에는 처리 결과(`released`/`kept`)를 같은 카드에 표시하는 안.
- **관리자 페이지 (작성자 제안)**: Express가 `/admin` 화면과 JSON API를 제공하고, `admins` 테이블로 권한을 확인한 뒤 service role로 `auth.users`·`hidden_profiles`·`reports`·`appeals`를 조회하는 안. 결정 31의 3탭(처리 대기·전체 유저·처리 기록)과 이름 검색을 이 화면에 둔다.

### 미결 (임의 결정 금지)

- 없음.

## How

- 이 ADR은 #41–#44와 0.3.6–0.3.8 구현의 설계 기준이 된다. 구현 순서는 결정 34의 0.3.6 프로필 → 0.3.7 채팅 → 0.3.8 운영을 따른다.
- 프로필 이미지 업로드·읽기와 채팅 전송은 브라우저 `supabase-js`가 맡고, Express는 서버가 나은 작업만 맡는다 — [ADR-0010](./0010-0.3-browser-supabase-js.md).
- 로그인 사용자 확인과 세션 수명은 [ADR-0004](./0004-0.3-session-and-stats.md), 방 Realtime 채널 재사용은 [ADR-0003](./0003-0.3-transport.md)을 따른다.
- 구현은 확정 결정 1–9·11–24·26–35를 그대로 따르며, 채팅 범위·보관은 결정 5·6, 제한은 결정 7, 표시는 결정 8, UI는 결정 14를 기준으로 한다. 채팅 금지는 결정 19·27, 업로드 UI는 결정 11, 가림 중 업로드는 결정 26을 따른다.
- 관리자 지정·가리기 판정·원본 처리·관리자 페이지는 결정 3·4·9·12·13·22·23·31을 기준으로 한다. 관리자 페이지 구성·목록 표시 항목은 결정 31을 따른다. 업로드 형식·용량 검사는 결정 2를 기준으로 버킷 설정과 브라우저 안내를 함께 둔다.
- 신고 접수·자동 의심 차단·운영자 위반 확정은 결정 18–24·27·28을 기준으로 한다.
- 이의제기 접수·표시·처리는 결정 29·30·32를 기준으로 한다. 기본·봇 아바타는 결정 33을 따른다.
- 신고 의심 차단의 채팅 금지 해제는 결정 35에 따라 사진 복구·채팅 허용·업로드 허용을 한 번에 함께 푼다.
