# ADR-0016: 0.3.6 프로필 이미지·관리자 가리기·방 채팅

- 상태: accepted
- 날짜: 2026-10-18
- 관련: [ADR-0010](./0010-0.3-browser-supabase-js.md) (브라우저 우선·CDN `supabase-js`), [ADR-0004](./0004-0.3-session-and-stats.md) (세션), [ADR-0003](./0003-0.3-transport.md) (전송·Realtime)
- 관련 이슈: #41, #42, #43, #44
- 출처: 2026-10-18 사용자 결정 (설계 인터뷰 9건)

## Why

#44 설계 인터뷰에서 0.3.6 패치의 프로필 이미지·관리자 가리기·방 채팅에 대한 사용자 결정 9건이 나왔다. #41–#43 구현을 시작하기 전에 저장 위치·형식·관리자 판별·가리기 범위·가린 원본 처리·채팅 범위·보관·제한·표시 방식을 한 문서에 고정해야 한다. 이 ADR은 사용자가 고른 결정만 확정으로 적고, 구현 수단과 아직 묻지 않은 항목을 분리한다. 기존 제약은 브라우저 우선([ADR-0010](./0010-0.3-browser-supabase-js.md)), 세션([ADR-0004](./0004-0.3-session-and-stats.md)), 전송([ADR-0003](./0003-0.3-transport.md))을 따른다.

## What

   선택지 설명: "브라우저 supabase-js로 바로 업로드(ADR-0010 브라우저 우선과 맞음). 읽기는 공개 URL, 쓰기는 본인 폴더만(RLS). 가장 단순."
2. **파일 형식·용량 (#41) — 사용자 결정 (2026-10-18)**: 선택 라벨 원문 "PNG·JPEG·WebP, 1MB (Recommended)".
   선택지 설명: "버킷 설정(allowed MIME·file size limit)으로 서버가 강제. 브라우저는 올리기 전 같은 검사로 안내만. 리사이즈 없음."
3. **관리자 판별 (#42) — 사용자 결정 (2026-10-18)**: 선택 라벨 원문 "DB admins 테이블 (Recommended)".
   선택지 설명: "user_id를 넣은 테이블을 RLS·서버가 조회. 추가·삭제는 Supabase 대시보드에서 직접. 배포 없이 바꿀 수 있고 SQL로 보여 주기 쉬움."
4. **가리기 범위 (#42) — 사용자 결정 (2026-10-18)**: 선택 라벨 원문 "프로필 이미지만 기본 아바타로 (Recommended)".

5. **채팅 범위 (#43) — 사용자 결정 (2026-10-18)**: 선택 라벨 원문 "게임 방 안에서만 (Recommended)".

   선택지 설명: "관리자가 가리면 서버가 버킷에서 그 이미지를 지움. 주소로도 못 봄. 풀면 본인이 다시 올려야 함. 공개 버킷 구조는 그대로."

### 제안 (공학적 수단, 사용자 명시 선택 아님)

- **버킷·경로**: 공개 버킷 이름은 `avatars`, 객체 경로는 `<user_id>/avatar`로 두는 안. 버킷 설정은 허용 MIME `image/png,image/jpeg,image/webp`, 파일 용량 한도 `1MB`로 두고, 쓰기 정책은 `auth.uid()`가 경로 첫 조각과 같은 경우만 허용하는 안.
- **테이블**: `public.admins (user_id uuid primary key references auth.users(id))`와 `public.hidden_profiles (user_id uuid primary key references auth.users(id), hidden_by uuid not null, hidden_at timestamptz not null default now())`를 두는 안. 가리기 해제는 행 삭제로 처리. 두 테이블 읽기는 RLS·서버 조회로 제한.
- **가린 원본 삭제**: 결정 9의 삭제를 서버가 service role key로 Storage의 `<user_id>/avatar` 객체를 지우는 방식으로 구현하는 안.
- **마이그레이션**: 위 테이블·정책·버킷 설정을 `supabase/migrations/<timestamp>_profile_admin_chat.sql` 한 파일에 담는 안. 기존 이름 규칙(`20261016163800_game_schema.sql`, `20261017062000_tutorial_mode.sql`)을 따름.
- **채팅**: 기존 방 Realtime 채널에 `chat` 이벤트를 더해 `{ userId, name, text, at }`를 실시간 전송하고 DB 테이블은 만들지 않는 안. 길이·간격 제한과 수신 측 자르기는 확정 결정 7을 클라이언트에서 구현.
- **프로필 표시**: 공개 URL은 `<user_id>/avatar` 경로로 만들고, `hidden_profiles`에 있으면 기본 아바타로 바꿔 표시하는 안. 기본 아바타 자산은 미결.
- **이슈 표기**: #41–#44 본문의 "0.4" 표현은 마일스톤 0.3.0·패치 0.3.6과 어긋난다. 이슈 본문 수정은 사용자 승인 후에 한다.

### 미결 (임의 결정 금지)

- 관리자 화면 위치·형태.
- 프로필 이미지 업로드 UI 위치·형태.
- 채팅 입력·목록 UI 배치.
- 가려진 본인에게 보여 줄 안내 문구.
- 기본 아바타와 봇 아바타의 디자인.
- 구현 패치 분할.

## How

- 이 ADR은 #41–#43 구현의 설계 기준이 된다. 구현 순서와 패치 분할은 미결이다.
- 프로필 이미지 업로드·읽기와 채팅 전송은 브라우저 `supabase-js`가 맡고, Express는 서버가 나은 작업만 맡는다 — [ADR-0010](./0010-0.3-browser-supabase-js.md).
- 로그인 사용자 확인과 세션 수명은 [ADR-0004](./0004-0.3-session-and-stats.md), 방 Realtime 채널 재사용은 [ADR-0003](./0003-0.3-transport.md)을 따른다.
- 구현은 확정 결정 1–9를 그대로 따르며, 채팅 범위·보관은 결정 5·6, 제한은 결정 7, 표시는 결정 8을 기준으로 한다.
- 관리자 지정·가리기 판정·가린 원본 삭제는 결정 3·4·9를 기준으로 하고, 화면 위치·형태는 미결이다. 업로드 형식·용량 검사는 결정 2를 기준으로 버킷 설정과 브라우저 안내를 함께 둔다.
- 남은 화면·디자인·패치 분할은 미결 목록에 따라 사용자 결정 뒤에 구현한다.
