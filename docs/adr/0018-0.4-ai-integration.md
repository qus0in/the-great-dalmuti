# ADR-0018: 0.4 AI 통합 결정

- 상태: accepted
- 날짜: 2026-10-20
- 관련: [ADR-0003](./0003-0.3-transport.md), [ADR-0007](./0007-0.3-structure.md), [ADR-0008](./0008-0.3-code-conventions.md), [ADR-0010](./0010-0.3-browser-supabase-js.md), [ADR-0016](./0016-0.3.6-profile-admin-chat.md)
- 관련 이슈: [#63](https://github.com/qus0in/the-great-dalmuti/issues/63)
- 출처: #63 본문 상위 결정 12건, 2026-10-20 인터뷰 7건

## Why

0.4 AI 통합의 상위 정책 12건이 이슈 #63 본문에만 머물러 있어 저장소의 공식 결정 문서로 관리되지 않았다. 운영 원칙에 따라 설계 결정은 본 ADR 기록으로 승격해야 한다. 0.4 선행 확인에서 기존 ADR과 충돌 4건이 나왔고, 사용자가 2026-10-20 인터뷰에서 해소 방향을 골랐다. 본 ADR은 사용자가 고른 결정만 확정으로 적고, 작성자 제안과 아직 묻지 않은 항목을 분리한다.

#### C. 2026-10-20 후속 결정: API 자격 증명 (출처: 2026-10-20 사용자 프롬프트)

- 사용자 원문(비밀값 없음): "groq, gemini, nim, cf 모두 api key 발급 예정이고, .env로 제공할 예정. 관련하여 노드 자체 기능으로 env load하게 하고 (최신 기능이 있음) 나머지 사항들 진행. 우선 0.3.x 최신에서의 사용자 리뷰 가능 상태인지 확인하고 가능하다면 링크 제공."
- 확정: Groq·Gemini·NVIDIA NIM·Cloudflare 4곳 모두 API 키를 발급한다. 키는 `.env`로 제공하며 커밋하지 않는다. 로컬은 Node 자체 기능 `--env-file-if-exists=.env`로 로드한다(이미 `npm start`/`npm run dev`에 적용, Node 22.9+). Render는 dashboard 환경변수를 사용한다.
- 미결: 모델 ID·기능별 우선순위·무료 한도·쿼터 수치는 본 절에서 확정하지 않으며, 위 미결 목록의 해당 항목으로 남는다.

### 제안 (공학적 수단, 사용자 명시 선택 아님)

아래는 작성자 제안이며 사용자가 명시적으로 고른 결정이 아니다. 확정 결정으로 다루지 않는다.

- AI 장애 응답 코드 (작성자 제안, 사용자 명시 선택 아님): AI 호출 실패와 Fallback 실패의 응답 코드를 ADR-0008의 HTTP 상태 코드 매핑에 보완하는 안. 기존 503 정의가 Supabase 장애에 한정되므로 AI 장애 표현 수단을 별도로 정하는 안.
- 중요 상황 판별 조건 (작성자 제안, 사용자 명시 선택 아님): Q4의 중요 상황 판별을 서버 도메인 로직으로 두어 기존 봇 실행 경로에서 분기하는 안. 정량 조건 수치는 미결로 남긴다.

### 미결 (임의 결정 금지)

아래는 사용자가 아직 결정하지 않은 항목이다. 담당자나 AI 에이전트가 임의로 선택·확정하지 않는다.

- 프로바이더별 구체 지원 모델과 모델 ID, 모델 버전 및 기능별 기본·예비 모델 우선순위 (출처: #63)
- LangChain과 LangGraph의 라이브러리 버전 및 구체 적용 경계 (출처: #63)
- 중요한 전략 판단 상황의 정량 조건, 프롬프트 및 행동 출력 스키마 (출처: #63)
- 타임아웃, Retry 횟수·간격, Fallback 전환 기준 (출처: #63)
- 제공자별 실제 무료 할당량 및 기능별 예산·쿼터 숫자 (출처: #63)
- 대화 기록 길이·보관과 삭제 구현, 권한 검증 상세 (출처: #63)
- 채팅 및 이미지 검열 임계값, 오류와 재검사·이의제기 절차 상세 (출처: #63)
- 봇별 페르소나, 채팅 빈도 및 감정 전이 조건 (출처: #63)
- 이미지 생성에 사용할 정확한 모델, 스타일·해상도·생성 수량과 검수 기준 (출처: #63)
- 품질·지연·비용 측정 목표 및 테스트 기준 (출처: #63)
- 챗봇과 검열 등 기능별 시간 상한 (출처: 2026-10-20 인터뷰 결정 4, 후속 인터뷰에서 결정)

## How

- 본 ADR이 0.4 AI 통합 결정의 단일 진실 원천이다. 다른 ADR은 본 ADR을 가리키며 결정 문장을 반복하지 않는다.
- 클래스 규칙과 관계: ADR-0008의 클래스 금지 원칙을 유지하고, `src/infra/ai` 안의 외부 라이브러리 클래스 사용만 좁은 예외로 둔다. `app`과 `domain`에는 함수형 포트만 노출한다.
- 업로드·채팅 경로와 관계: ADR-0016의 브라우저 직접 업로드와 브라우저 간 Realtime 전송 결정 중 AI 검열과 가드가 필요한 부분만 서버 경유로 대체한다. DB 미저장 원칙을 유지한다.
- 서버 권위와 비공개 보호: Q3의 규칙 엔진 권위와 Q7의 손패 보호는 ADR-0003의 서버 권위 원칙을 따른다. 본인 손패 조회와 프롬프트 주입은 서버가 인증 세션을 확인한 뒤 수행하며, 브라우저가 비공개 정보를 직접 다루지 않는다.
- 정적 에셋: Q12의 사전 생성 에셋 배포는 ADR-0007의 Express 정적 서빙 원칙을 따른다.
- 관련 이슈 매핑: #63이 본 ADR의 출처이며, 지원 모델 후보 조사와 운영 파라미터 승인, 패치 분할 계획은 후속 결정에서 다룬다. 후속 의사결정은 #63에 기록한다.
