# ADR-0014: 0.3.4 튜토리얼 모드 — 봇 3석 고정과 서버 추천·이유

- 상태: accepted
- 날짜: 2026-10-17
- 관련: [ADR-0003](./0003-0.3-transport.md) (규칙 판정은 서버), [ADR-0004](./0004-0.3-session-and-stats.md) (세션과 전적), [ADR-0011](./0011-0.3-game-progress.md) (게임 진행: 봇·전적)
- 출처: 2026-10-17 사용자 결정 (요청·결정 원문)
- 이력: 2026-10-17 결정 3의 전략을 힌트·봇 공통 보통 달무티 전략으로 변경했다.

## Why

사용자가 2026-10-17에 튜토리얼 모드가 필요하다고 결정했다. 원문: "튜토리얼 모드가 하나 필요할 것 같아.", "무조건 ai 3이랑만 하고 무엇을 왜 내야하는지 알려주는 모드". 사람 1석과 봇 3석이 브라우저에서 한 판을 끝내는 흐름은 0.3.3에서 갖춰졌다. 이 흐름 위에서 무엇을 왜 내야 하는지 알려주는 연습 모드를 얹는다. 이 ADR은 사용자가 확정한 결정만 기록한다.

## What

### 확정 결정

1. **형태 — 사용자 결정 (2026-10-17, 원문 "실제 판 위 힌트")**: 일반 솔로 판에서 힌트로 제공한다.
2. **일정 — 사용자 결정 (2026-10-17, 원문 "0.3.4 patch로 focus")**: 튜토리얼 모드는 0.3.4 patch로 진행한다.
3. **힌트 계산 — 사용자 결정 (2026-10-17, 원문 "서버가 추천·이유 제공")**: 튜토리얼 방에서는 서버가 내 차례마다 추천 카드와 한국어 이유를 내려준다. 2026-10-17 전략 변경 원문은 "보통 달무티 전략을 중심으로 진행", 적용 범위 원문은 "힌트와 봇 모두"다. 이에 따라 기존 봇 전략을 재사용하던 내용을 대체하여, 힌트와 봇이 같은 보통 달무티 전략 함수를 쓴다. 선일 때 약한 카드(높은 숫자)부터 털고, 강한 카드·어릿광대는 선을 되찾을 때 쓰도록 아끼며, 따라갈 때 이길 수 있는 가장 약한 대응을 고른다. [ADR-0003](./0003-0.3-transport.md)(규칙 판정은 서버)은 유지한다.
4. **전적 — 사용자 결정 (2026-10-17, 원문 "기록 안 함")**: 연습 판은 전적 집계에서 뺀다.
5. **좌석 — 사용자 결정 (2026-10-17)**: 항상 사람 1석 + 봇(AI) 3석.

### 미결 (임의 결정 금지)

1. 추천·이유 API의 형태(경로, 요청·응답 필드)는 사용자가 결정하지 않았다 — 구현 단계에서 정한다.
2. 힌트 표시의 세부(화면 위치, 문구 형식, 표시 시점)는 사용자가 결정하지 않았다 — 구현 단계에서 정한다.
3. 튜토리얼 판의 진입·구분 방식(모드 선택 UI, 판 식별)은 사용자가 결정하지 않았다 — 구현 단계에서 정한다.

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| 실제 판 위 힌트 + 서버 추천 (채택) | 솔로 판 흐름과 서버 규칙 판정을 그대로 재사용한다 | 내 차례마다 추천·이유 계산과 전송이 더해진다 | 0.3.4 patch로 작게 얹고 힌트 문구 품질을 계속 올릴 수 있다 | 힌트에 의존하거나 추천 품질이 낮으면 학습·신뢰가 떨어진다 |
| 별도 튜토리얼 화면·시나리오 | 학습 순서와 설명을 통제하기 쉽다 | 별도 구현·유지 비용이 들고 실제 판 흐름과 갈라진다 | 단계별 입문 과정을 따로 구성할 수 있다 | 플레이 흐름이 둘로 나뉘어 유지 부담이 커진다 |
| 힌트 없는 연습 모드 | 구현이 가장 작다 | "무엇을 왜 내야하는지 알려주는" 요청을 충족하지 못한다 | 없음 | 사용자 요청과 불일치한다 |

## How

- 일반 솔로 판(사람 1석+봇 3석) 흐름을 그대로 쓰고, 내 차례마다 서버가 추천 카드와 한국어 이유를 내려주면 화면이 표시한다.
- 추천·이유 계산과 봇 행동은 확정 결정 3의 공통 전략 함수를 사용한다. 판정 정본은 [ADR-0003](./0003-0.3-transport.md), 전적 집계·제외 경계는 [ADR-0004](./0004-0.3-session-and-stats.md), 봇·전적 진행은 [ADR-0011](./0011-0.3-game-progress.md)을 따르며 중복 기록하지 않는다.
- 미결(API 형태, 힌트 표시, 진입 방식)은 구현 단계에서 정한다. 완료 기준과 이슈는 0.3.4 작업 단위에서 정한다.
