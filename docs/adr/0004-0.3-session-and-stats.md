# ADR-0004: 0.3 세션과 전적

- 상태: draft (결정 채택, 인터뷰·리뷰 대기)
- 날짜: 2026-10-15
- 관련 이슈: [#21](https://github.com/qus0in/the-great-dalmuti/issues/21), [#23](https://github.com/qus0in/the-great-dalmuti/issues/23)
- 관련: [ADR-0001](./0001-0.3-play-scope.md) (플레이 범위), [ADR-0003](./0003-0.3-transport.md) (전송과 저장)
- 이력: [0.3 계획 프롬프트 로그](../prompt/2026-10-15-34-plan-0-3-ssr-express-supabase.md) (원문의 모듈 80줄 제한은 현재 100줄 제한이 대체)

## Why

로그인 유지 기간과 완료된 판의 전적 보존 범위를 정해야 한다. 사용자 선택(브라우저 세션 로그인, 모드별 누적 전적)을 확정으로 고정하고, 제안된 구현 수단과 미결을 분리한다. 확정 외의 내용을 결정된 것으로 다루지 않는다.

## What

### 확정 결정

1. 로그인은 브라우저 세션 동안만 유지한다. 자동 로그인(remember-me)을 두지 않으며, 브라우저를 종료하면 다음 방문에 다시 로그인한다.
2. 완료된 판의 누적 전적을 계정 단위로 저장해 다음 방문에도 표시한다. 총 판 수와 순위별 횟수를 기록한다. 진행 중인 판은 서버 재시작 시 폐기한다(서버 재시작 시 진행 판 폐기 유지).
3. 모드별로 분리 집계한다. 사람 1명인 판과 사람 2명 이상인 판을 별도로 저장하며, 각각 총 판 수와 순위별 횟수를 가진다.
4. 한 판에서 한 번이라도 봇이 대신한 사람은 그 판의 판 수·순위를 기록하지 않는다. 이후 복귀해도 소급하지 않으며, 방 전체가 아닌 개인 단위 제외이다. 나머지 적격자는 정상 기록하고, 봇을 상대로 뒀다는 이유만으로 대행으로 보지 않는다.

### 제안 (공학적 수단, 사용자 명시 선택 아님)

- 비지속 쿠키를 세션 전달 수단 후보로 제안한다. 브라우저 종료를 확실히 감지할 수단은 없으며(세션 복원이 쿠키를 복원할 수 있음), unload를 로그아웃 근거로 사용하지 않는다.
- 모드 분류 시점으로 라운드 시작 로스터를 제안한다. 미채택이며, 끊김·대체로 판의 분류를 바꾸지 않는다.

### 미결 사항

아래는 사용자가 정하지 않았으며 임의 결정 금지:

- 인증 세션 저장소·백킹 DB·보존 기간 (Supabase Auth는 채택됨, 전적 저장소는 Supabase Postgres로 확정([ADR-0003](./0003-0.3-transport.md)), 스키마·보존 기간은 미결)
- 모드 분류 스냅샷 시점

### 채택하지 않은 항목

리더보드·리플레이·전체 대전기록·승률·보너스 점수는 확정 기능이 아니다.

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| 브라우저 세션 로그인(확정) | 구현 단순, 방치 계정 없음 | 재방문 로그인 필요 | 세션 설계 단순 | 복원 동작 오해 |
| 영속 로그인(미채택) | 재방문 편의 | 세션 장기 관리 | 편의 확장 | 보안·만료 복잡 |
| 누적 전적 보존(확정) | 성장 체감 | 저장소 필요 | 모드별 분석 | 분류·귀속 설계 |
| 판 종료 시 폐기(미채택) | 저장 불필요 | 기록 소실 | 없음 | 동기 상실 |

## How

- 강제 퇴장·복귀·재시작 규칙은 [ADR-0001](./0001-0.3-play-scope.md)에 따르며 중복 기록하지 않는다.
- [#21](https://github.com/qus0in/the-great-dalmuti/issues/21)은 로그인, [#23](https://github.com/qus0in/the-great-dalmuti/issues/23)은 전적 귀속과 관련되며, 본 문서에서는 이슈를 변경하지 않는다.
