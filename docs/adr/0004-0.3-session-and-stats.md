# ADR-0004: 0.3 세션과 전적

- 상태: draft (결정 채택, 인터뷰·리뷰 대기)
- 날짜: 2026-10-15
- 관련 이슈: [#30](https://github.com/qus0in/the-great-dalmuti/issues/30), [#31](https://github.com/qus0in/the-great-dalmuti/issues/31), [#35](https://github.com/qus0in/the-great-dalmuti/issues/35)
- 관련: [ADR-0001](./0001-0.3-play-scope.md) (플레이 범위), [ADR-0003](./0003-0.3-transport.md) (전송과 저장)
- 이력: [0.3 계획 프롬프트 로그](../prompt/2026-10-15-34-plan-0-3-ssr-express-supabase.md) (원문의 모듈 80줄 제한은 현재 100줄 제한이 대체)

## Why

로그인 유지 기간과 완료된 판의 전적 보존 범위를 정해야 한다. 사용자 선택(브라우저 세션 로그인, 모드별 누적 전적)을 확정으로 고정하고, 제안된 구현 수단과 미결을 분리한다. 확정 외의 내용을 결정된 것으로 다루지 않는다.

## What

### 확정 결정

1. 로그인은 브라우저 세션 동안만 유지한다. 자동 로그인(remember-me)을 두지 않으며, 브라우저를 종료하면 다음 방문에 다시 로그인한다.
2. 완료된 판의 누적 전적을 계정 단위로 Supabase Postgres에 저장해 다음 방문에도 표시한다. 총 판 수와 순위별 횟수를 기록한다. 진행 중인 판은 서버 재시작 시 폐기한다(서버 재시작 시 진행 판 폐기 유지).
3. 모드별로 분리 집계한다. 사람 1명인 판과 사람 2명 이상인 판을 별도로 저장하며, 각각 총 판 수와 순위별 횟수를 가진다. 분류는 카운트다운 종료·라운드 시작 시점의 사람 수로 확정하며, 이후 끊김·봇 대행으로 재분류하지 않는다.
4. 한 판에서 한 번이라도 봇이 대신한 사람은 그 판의 판 수·순위를 기록하지 않는다. 이후 복귀해도 소급하지 않으며, 방 전체가 아닌 개인 단위 제외이다. 나머지 적격자는 정상 기록하고, 봇을 상대로 뒀다는 이유만으로 대행으로 보지 않는다.
5. 로그인은 브라우저 supabase-js로 수행하고 세션은 sessionStorage에 둔다. 탭별 세션이므로 새 탭·초대 링크를 새 탭으로 열면 다시 로그인한다(수용된 tradeoff). axios는 `Authorization: Bearer`로 access JWT를 보내고 Express가 서버에서 검증하며, 동일 JWT로 Realtime 구독을 인가한다. 토큰은 JS에 노출되며 HttpOnly가 아니다.
6. 토큰 리프레시·JWT 검증 위임은 [ADR-0003](./0003-0.3-transport.md) 확정 8에 따른다.

### 미결 사항

아래는 사용자가 정하지 않았으며 임의 결정 금지:

- 전적 스키마·보존 기간

### 채택하지 않은 항목

리더보드·리플레이·전체 대전기록·승률·보너스 점수는 확정 기능이 아니다. 서버 PKCE + HttpOnly 세션 쿠키 + 토큰 엔드포인트 방식도 기각되었다.

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| 브라우저 세션 로그인(확정) | 구현 단순, 방치 계정 없음 | 재방문 로그인 필요 | 세션 설계 단순 | 복원 동작 오해 |
| 영속 로그인(미채택) | 재방문 편의 | 세션 장기 관리 | 편의 확장 | 보안·만료 복잡 |
| 누적 전적 보존(확정) | 성장 체감 | 저장소 필요 | 모드별 분석 | 분류·귀속 설계 |
| 판 종료 시 폐기(미채택) | 저장 불필요 | 기록 소실 | 없음 | 동기 상실 |
