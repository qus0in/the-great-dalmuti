# ADR-0007: 0.3 디렉터리 구조와 자산 위치

- 상태: accepted
- 날짜: 2026-10-16
- 관련: [ADR-0005](./0005-0.3-migration-boundaries.md), [ADR-0006](./0006-0.3-tdd-bdd-and-layers.md)
- 관련 이슈: [#26](https://github.com/qus0in/the-great-dalmuti/issues/26), [#29](https://github.com/qus0in/the-great-dalmuti/issues/29)
- 출처: 0.3 ADR 인터뷰 결정 39·40 (2026-10-16, 추천안 채택)

## Why

0.3부터 서버와 클라이언트 코드가 함께 늘어나고([ADR-0006](./0006-0.3-tdd-bdd-and-layers.md)의 4레이어 도입), 0.2 정적 화면을 계승한 0.3 정적 뷰([#29](https://github.com/qus0in/the-great-dalmuti/issues/29))와 정적 자산 배포 기준([#26](https://github.com/qus0in/the-great-dalmuti/issues/26))이 이미 이슈로 고정되어 있다. 코드와 화면 자산을 어느 경로에 둘지, 그리고 GitHub Pages(0.2 미리보기)와 Render(0.3 서비스)의 역할을 한 번만 정해야 이후 이슈가 이를 재결정하지 않는다. 자산 위치는 0.2 프로토타입(`dist/`)과 0.3 서비스(`src/`)가 공존하는 저장소에서 충돌 지점이므로 이번에 확정한다.

## What

### 확정 결정

1. **0.3 자산 위치** (사용자 선택, 2026-10-16): `dist/`는 0.2 Pages 미리보기로 동결한다. 0.3 화면은 `dist/`에서 복사해 레이어 아래에서 진화시킨다(`src/ui/public/`), Express가 서빙한다. CSS가 두 사본으로 분기하는 트레이드오프를 수용한다. (결정 39, #26의 자산 위치 옵션)
2. **레이어 루트** (사용자 선택, 2026-10-16): `src/`에 레이어를 위에 두고 그 아래에 피처를 둔다(`src/ui`, `src/app`, `src/domain`, `src/infra`; 피처 예: `src/app/auth`). 테스트는 피처 옆에 `*.test.js`로 둔다. (결정 40, #26의 "레이어 위·피처 아래")

레이어 의존 규칙의 단일 원천은 [ADR-0005](./0005-0.3-migration-boundaries.md)(레이어 역할·포트 정의)이며, 레이어 목록과 순서는 [ADR-0006](./0006-0.3-tdd-bdd-and-layers.md)·[ADR-0001](./0001-0.3-play-scope.md)에서 온다. 본 ADR은 재결정하지 않고 디렉터리 배치가 따르는 규칙만 인용한다: 의존 방향 `ui` → `app` → `domain`, `infra`는 `app`/`domain`이 정의한 포트를 구현, `domain`은 외부 의존 없음. 정적 뷰 이식([#29](https://github.com/qus0in/the-great-dalmuti/issues/29))은 `src/ui/public/`을 기준으로 한다.

역할 구분(#26): GitHub Pages는 0.2 프로토타입 미리보기(`dist/` 동결), Render는 0.3 서비스(Express가 `src/ui/public/` 정적 뷰와 API를 서빙)를 담당한다.

### 미결 (임의 결정 금지)

없음.

### 대안 비교 (작성자 분석, 사용자 결정 아님)

| 대안 | 강점 | 약점 | 기회 | 위협 |
| --- | --- | --- | --- | --- |
| `dist/` 공유 유지 (0.3도 `dist/`를 그대로 사용, 미채택) | CSS·마크업 단일 원본, 0.2↔0.3 동기화 비용 없음 | 0.2 미리보기와 0.3 진화가 한 경로에서 충돌하고 0.2 회귀와 0.3 변경을 분리할 수 없음 | 두 마일스톤의 디자인 동기화 자동화 | #15(종료)의 `dist/` 전용 업로드 기준과 0.2 동결 훼손, 미리보기가 0.3半成品을 노출 |
| `src/ui/public/`로 복사·분기 (채택, 결정 39) | `dist/` 동결 보존으로 #15 기준 안전, 0.3이 자유롭게 진화 | CSS·마크업 2벌 유지보수 중복 | 토큰·정합 검사로 분기를 통제 | 디자인 drift |

## How

- **이력 (종료 이슈)**: [#15](https://github.com/qus0in/the-great-dalmuti/issues/15)는 종료되었으며, 완료 기준("워크플로가 `dist/`만 Pages 아티팩트로 업로드")은 `dist/` 동결 덕분에 유지된다 — `dist/`는 삭제·이동되지 않고 0.2 미리보기 아티팩트 원본으로 남는다.
- **이슈 매핑**: [#26](https://github.com/qus0in/the-great-dalmuti/issues/26) 프로젝트 골격과 구조·의존 규칙(본 ADR이 자산 위치·레이어 배치·역할 구분을 기록), [#29](https://github.com/qus0in/the-great-dalmuti/issues/29) hall·play 정적 뷰 이식(`src/ui/public/` 기준).
- 구조를 바꾸는 결정은 이 ADR을 `superseded` 처리하고 새 ADR로 잇는다(삭제·재작성 금지, `adr` 스킬 규칙). 실무 지도는 `docs/structure.md`가 링크로 가리키며 재기술하지 않는다.
