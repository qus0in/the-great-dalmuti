# ADR-0017: 0.3.7 참가 코드 대기실과 운영 기능 숨김 배포

- 상태: accepted
- 날짜: 2026-10-18
- 관련: [ADR-0016](./0016-0.3.6-profile-admin-chat.md), [ADR-0013](./0013-0.3.3-browser-e2e-and-module-placement.md)
- 관련 이슈: #43, #53, #42, #51
- 출처: 2026-10-18 사용자 결정 두 건 (질문·답 원문)

## Why

0.3.7(#43, #53) 채팅 브라우저 E2E를 통과한 후 실측 과정에서 사용성 및 배포 정합성 문제가 확인되었다. 첫째, `/play` 진입 시 항상 새 방을 만들고 봇으로 채워 시작하므로, 다른 사람이 같은 방에 들어올 수 있는 화면(참가 코드)이 없어 실제 사용자 간 채팅을 수행할 방법이 없었다(서버 `joinRoom` API는 이미 구현되어 있음). 둘째, 선행 작업 진행 과정에서 0.3.7(채팅·참가 코드)과 0.3.8 일부(신고·이의제기 화면, 신고 서버 로직)가 동일 파일군에 함께 작성되어 있어, 관리자 페이지(#42) 없이 그대로 배포할 경우 신고 누적(3건)으로 인한 자동 차단이 발생했을 때 이를 해제할 방법이 없었다.

이에 사용자는 2026-10-18 1) 0.3.7에 참가 코드 흐름을 추가하여 채팅 기능의 실효성을 확보하고, 2) 0.3.7을 먼저 배포하되 신고·이의제기 버튼은 0.3.8 배포 전까지 숨김 처리하기로 결정했다. 이 결정은 [ADR-0016 결정 34](./0016-0.3.6-profile-admin-chat.md#what)의 3개 패치 분할(프로필 → 채팅 → 운영) 원칙을 유지하며 안전하게 0.3.7을 선출시하기 위한 아키텍처 및 구현 기준을 확정한다. 기존 제약은 브라우저 우선([ADR-0010](./0010-0.3-browser-supabase-js.md)), 브라우저 E2E([ADR-0013](./0013-0.3.3-browser-e2e-and-module-placement.md)), 채팅 기본 규칙([ADR-0016](./0016-0.3.6-profile-admin-chat.md))을 따른다.

## What

### 확정 결정

1. **참가 코드 흐름 추가 (#53) — 사용자 결정 (2026-10-18)**
   - 질문: "채팅 E2E는 통과했지만, 지금 /play는 들어갈 때마다 새 방을 만들고 봇으로 채워 시작합니다. 다른 사람이 같은 방에 들어오는 화면(참가 코드)이 없어 실제로는 사람끼리 채팅할 방법이 없습니다(서버 join API는 있음). 어떻게 할까요?"
   - 선택 라벨 원문: `0.3.7에 참가 코드 흐름 추가 (Recommended)`
   - 선택지 설명: 방 만든 사람에게 참가 코드·링크(/play?code=XXXX)를 보여 주고, 링크로 들어온 사람은 joinRoom. 시작은 방장이 '시작' 버튼으로(빈 자리는 봇). 이슈 하나 추가. 채팅이 실제로 쓸모 있게 됨.

2. **신고 버튼 숨김 배포 (#42, #51) — 사용자 결정 (2026-10-18)**
   - 질문: "선행 작업 때문에 0.3.7(채팅·참가 코드)과 0.3.8 일부(신고·이의제기 화면, 신고 서버)가 같은 파일에 섞여 있습니다. 지금 0.3.7만 배포하면 관리자 페이지 없이 신고 3건으로 자동 차단이 걸려도 풀 방법이 없습니다. 어떻게 배포할까요?"
   - 선택 라벨 원문: `0.3.7 먼저, 신고 버튼은 숨김 (Recommended)`
   - 선택지 설명: 0.3.7을 지금 PR로. 신고 버튼·이의제기 버튼은 0.3.8 배포 전까지 켜지지 않음(설정 한 곳에서 끔). 0.3.8에서 관리자 페이지와 함께 켬. 결정 34의 3개 패치 유지.

### 제안 (공학적 수단, 사용자 명시 선택 아님)

- **/play?code= 주소 교체**: 방 생성 직후 브라우저 주소창을 히스토리 적재 없이 교체하기 위해 `window.history.replaceState`를 호출하여 `/play?code=${encodeURIComponent(joinCode)}` 형식으로 반영하는 안 (`src/ui/public/js/play.js#L78`, `src/ui/public/js/play-lobby.js#L37`).
- **기존 좌석 재사용/참가**: URL 파라미터 `code`로 방에 접속할 때, 이미 해당 방에 배정된 내 좌석이 있다면 좌석 정보를 재사용하고, 배정된 좌석이 없을 때만 `api.joinRoom(code)`를 호출하여 신규 참가하는 안 (`src/ui/public/js/play-lobby.js#L9-L24`).
- **대기 상태 Realtime 갱신**: 대기실 진입 시점부터 `subscribeGame`을 통해 Realtime 브로드캐스트 채널을 구독하고, 참가자 입장 등 방 변경 이벤트 수신 시 `api.getRoom(code)`를 호출하여 대기실 좌석 현황을 실시간 동기화 및 렌더링하는 안 (`src/ui/public/js/play.js#L55-L66`, `src/ui/public/js/play.js#L94`, `src/ui/public/js/play-lobby.js#L79-L99`).
- **방장 시작**: 0번 좌석 사용자(방 개설자)에게만 게임 시작 권한(`canStart: mySeat === 0 && publicState?.phase === 'waiting'`)을 부여하고 '게임 시작' 버튼을 활성화하며, 방장이 시작 버튼 클릭 시 `api.startGame(code)`를 호출하여 빈 좌석을 봇으로 채우고 대결을 시작하는 안 (`src/ui/public/js/play-lobby.js#L60-L77`, `src/ui/public/js/play-lobby-view.js#L58-L64`).
- **features.js의 MODERATION_UI 스위치**: 0.3.8 선행 구현된 신고 및 이의제기 화면 UI 노출을 비활성화하기 위해 중앙 설정 파일에 `export const MODERATION_UI = false;`를 선언하고, 신고 진입 컴포넌트 및 이의제기 UI에서 이 플래그를 참조하여 버튼 렌더링을 차단하는 안 (`src/ui/public/js/features.js#L2`, `src/ui/public/js/play-report.js#L9`, `src/ui/public/js/profile-appeal.js#L54`, `src/ui/public/js/report-entry.js#L4`, `src/ui/moderation-flag.test.js#L20`).

### 미결 (임의 결정 금지)

1. **링크 복사 성공 안내 유무**: 대기실에서 '초대 링크 복사' 버튼 클릭 시 클립보드 복사 성공을 알리는 토스트나 시각적 안내 문구를 화면에 제공할지 여부는 사용자가 결정하지 않았다.
2. **데스크톱 채팅 열림 시 3열→스택 트레이드오프 수용 여부**: 데스크톱 화면에서 오른쪽 접이식 채팅 패널이 열렸을 때 경기장(아레나)의 3열 배치가 세로 스택으로 전환되는 레이아웃 트레이드오프를 수용할지 여부는 사용자 확인 대기 상태다.
3. **숨김 기간 중 직접 API 신고 위험 대응**: UI 버튼만 숨겨져 있는 상태에서 브라우저 개발자 도구나 직접 HTTP 요청을 통해 신고 API를 호출할 수 있는 보안 위험에 대해 서버 차원의 차단 또는 무시 처리를 둘지 여부는 사용자가 결정하지 않았다.

## How

- 참가 코드 흐름 구현:
  - `src/ui/public/js/play.js`와 `src/ui/public/js/play-lobby.js`에서 URL의 `code` 쿼리 파라미터를 파싱한다.
  - 방 개설 시 URL을 `/play?code=...`로 교체(`history.replaceState`)하고, 대기실 뷰를 렌더링한다.
  - 링크를 통해 유입된 사용자는 `loadCodeRoom`을 통해 기존 좌석 재사용 또는 `api.joinRoom`으로 참가한다.
  - Realtime 채널(`subscribeGame`)을 대기실부터 구독하여 참가자 입장 시 대기실 좌석 상태를 동기화하고, 방장(0번 좌석)이 시작 버튼을 누르면 `api.startGame`을 호출한다.
  - 브라우저 E2E 검증은 [ADR-0013](./0013-0.3.3-browser-e2e-and-module-placement.md)의 headless Chrome 테스트 세션 주입 방식을 준용한다.
- 신고 기능 숨김 플래그:
  - `src/ui/public/js/features.js`의 `MODERATION_UI = false` 설정을 통해 클라이언트 신고 버튼 및 이의제기 버튼 노출을 비활성화한다.
  - 0.3.8 관리자 페이지(#42, #51) 배포 시점에 해당 플래그를 활성화하여 운영 기능을 정식 릴리스한다.
- 기존 아키텍처 및 결정 준수:
  - 채팅 범위([ADR-0016 결정 5](./0016-0.3.6-profile-admin-chat.md#what))와 접이식 채팅 패널 UI([ADR-0016 결정 14](./0016-0.3.6-profile-admin-chat.md#what))를 유지하며, 재서술하지 않는다.
  - 패치 분할 원칙([ADR-0016 결정 34](./0016-0.3.6-profile-admin-chat.md#what))에 따라 0.3.7(방 채팅·참가 코드 대기실)을 선배포하고 0.3.8(운영 관리자)을 후속 배포한다.
  - 관련 이슈 매핑: #43(방 채팅), #53(참가 코드 대기실), #42(프로필 가리기·관리자), #51(신고·이의제기 운영).
