# orchestrate
Orchestrator allowed actions only: ask user; write tmp/<task>/ briefs, contracts, decision ledgers, handoff snapshots; dispatch/notify/wait; read reports/diffs/gate logs; run read-only deterministic gates (`scripts/verify.sh <task> [rules|ui|all]`, skill check scripts) and read their logs; read-only live-state queries (git/gh/herdr); final review; commit/push via skill `git-flow`.
Orchestrator never does anything else, even unrequested: scaffolding (`new-skill.sh`, index sync), code/doc/skill/AGENTS edits, prompt-log entries, issue/release/wiki/gh writes, gate fixes -> worker units.
Start automatically for non-trivial work; separate orchestration/delegation request not required. One-step trivial answer -> respond directly (answer, no file change).
Delegation transport: existing Herdr worker panes dispatched via scripts/dispatch.sh only. Never use built-in collaboration spawn/followup/subagent APIs; tool availability is not authorization to substitute delegation backend.
Before dispatch: resolve live workspace/self via scripts/context.sh and verify worker. If Herdr unavailable, context missing, or no ready worker, follow discovery/start/escalation below; never silently replace with native subagents or self-implement.

Find workers: `scripts/context.sh [--workspace ID --self-pane ID]` -> workspace/self IDs (JSON, exit!=0 = unknown, not "no workers"); `scripts/workers.sh [--idle] [--model] [--workspace <ID> --self-pane <ID>]` (output: `<target> <agent> <status> [<model> <effort>]`; model may be multi-word, `?` if unknown).
Assign by capability: identify model (kind + status line), map to tier (references/models.md), assign by tier; reviewer should differ in family from author.
Plan: split into units with disjoint file ownership; shared scaffolding needed by parallel units (new-skill.sh, index sync) -> first unit's worker, then fan out.
Unit sizing (S3): each brief sized for ~10 min of target worker's tier; larger work split before dispatch. Declare any inherently long step (e2e, external API, installs/builds) with expected duration up front.
Briefs: `tmp/<task>/brief-<worker>.md` (ordered why -> what -> how; goal, owned, forbidden, frozen acceptance criteria, report path `tmp/<task>/report-<worker>.md` (STAR)).
Korean docs (S15): decision-ledger/brief quotes feeding Korean docs are written in Korean; ko-doc briefs add a pre-report non-Korean token scan (kana, English verbs).
Scope freeze (S1): acceptance criteria frozen at dispatch; changing them requires user approval. Worker: stay within owned files and acceptance criteria; report other issues without fixing.
Dispatch non-blocking: `scripts/dispatch.sh [--workspace <ID> --self-pane <ID>] [--notify <pane>] [--wait-idle <sec>] [--then <reviewer-pane> <review-brief>] [--dry-run] [--force-existing-report] <target> <brief-path>` (no completion wait; --wait-idle rechecks target status ~5s intervals until idle/done or <sec>); rejects an existing report path found in either brief unless its first line is `status: in-progress` (restartable) or `--force-existing-report`; --dry-run prints the same prompt without sending it. Returns start timestamp on stdout (save in `tmp/<task>/dispatch-<worker>.log`; elapsed time via `scripts/elapsed.sh`). Each real dispatch appends `<UTC> dispatched <target> <unit> model=<model effort>` to `tmp/<task>/dispatch.log` + `tmp/<task>/state.md` (model from `workers.sh --model`, `?` if unknown); footer adds the worker's two resilience instructions (report first line `status: in-progress`, max 3 `checkpoint.sh <task> <unit> "<summary>" "<next>"`).
Event-driven by worker callbacks (S5): orchestrator runs no per-unit polling or watch loops; acts on callbacks sent via `scripts/notify.sh <target-pane> <report-path> [msg]` (appends durable record to `tmp/<task>/callbacks.log` first, then prompts target with retry backoff). Orchestrator sets exactly one fallback timer per unit for S3 10-min triage (timer, not watching); on fallback timer firing, orchestrator reads `tmp/<task>/callbacks.log` before triaging (S7). Review chain flow: author -> (if review brief given via --then) dispatches review brief to reviewer itself (reviewer must be idle; if busy -> notify orchestrator instead) -> reviewer notifies orchestrator with verdict. Blocked/failed workers notify immediately.
Timebox triage (S3): on fallback timer expiry or worker busy >10 min without callback, orchestrator triages once (pane read allowed) and classifies exactly one: (1) capability shortfall -> split unit or reassign to higher tier; (2) inherently long task (declared in brief, or e2e/external API evident) -> extend with explicit new timebox; (3) self error (provider error, crash, stuck prompt, dialog, loop) -> recover or reassign (~5 min provider rule). Record classification + evidence in `tmp/<task>/` and harness signal if it reveals a gap. At the fallback timer first run `scripts/health.sh <task>`; verdict lost/swapped/provider-error/context-high -> resume the unit via `scripts/resume.sh` and reassign it.
Checkpoint: workers append durable progress to `tmp/<task>/progress-<unit>.md` via `scripts/checkpoint.sh <task> <unit> "<summary>" "<next>"` (exit 1 if task dir missing, 2 on bad args).
Resume: orchestrator regenerates continuation brief to stdout via `scripts/resume.sh <brief-path> [--lines N]` (cites original brief, recent progress, report status, and owned git status).
Health: `scripts/health.sh <task> [--context-high N]` (triage-time only, never ambient) diffs `tmp/<task>/dispatch.log` units against progress/reports and live panels and prints per-unit verdicts `ok|lost|swapped|provider-error|context-high`.All workers busy -> queue unit, dispatch on first settle; never self-implement (no native subagents, no direct edits).
Missing/empty Herdr caller IDs, handoff, identity: skill handoff (scripts/snapshot.sh, scripts/takeover.sh; never identify caller from focus/cwd; verify backend=Herdr).
Peer review (S1): before dispatching a reviewer, snapshot the author's uncommitted outputs to `tmp/<task>/snapshot-<unit>.tar.gz` (tar.gz, never a plain directory copy — `node --test` discovers `tmp/` test files) so reviewer edits cannot be mistaken for the author's; reviewer must leave them identical — any change is a scope violation -> triage.
Peer review (S1): reviewer != author on Herdr panes writes `tmp/<task>/review-<reviewer>.md` (STAR form); judge strictly against unit's original acceptance criteria — findings outside them are out-of-scope observations, never blocking.
Fix rounds (S1): carry blocking findings only (author fixes, max 2 rounds). Non-blocking and out-of-scope findings never become new units or fix-round items; record to harness ledger or propose to user.
Non-owned gate block (S10): worker stops, notifies status=blocked with the proposed one-line change; never edits outside owned files; orchestrator dispatches it as its own unit.
Final review: read machine gate output (`scripts/verify.sh <task> [rules|ui|all]`; logs `tmp/<task>/verify-<gate>.log`), reports/reviews, and the diff; accept or new brief. Never fix; never reproduce automated checks. Commit/push via skill `git-flow` after acceptance.
Gates/reruns: `verify.sh <task> [rules|ui|all]` runs the applicable gates once per checkpoint (rules = codify check.sh, ui = ui-prototype check.sh) and logs under `tmp/<task>/`; reuse valid passed evidence by workflow policy — never reuse failures; rerun only on relevant input change, repair, or stated risk (AGENTS.md Verification).
Project values (ui gate target path) live in `.agents/project.conf`; empty/missing conf = generic defaults (ui gate skipped).
Parallel scope (S11): briefs scope gates to owned files while parallel units are in flight; repo-wide gates run at orchestrator checkpoints.
Blocked worker: read pane/report then escalate — pane reads only for blocked/errored/stalled/triage work, not routine polling. No idle workers: ask user or `herdr agent start`. Never substitute native subagents.
User-reported failure (S17): treat as our defect first — answer with a fix unit or proposal; never correct the user's behavior (state facts only alongside the fix).
Provider errors: reassign a worker that errors for ~5 min (references/models.md).
Orchestrator never runs headless/visual QA itself; assign visual/headless verification to a worker and read its report/PNGs. Visual claims (S24): UI briefs require every visual claim in the report to cite its PNG path; reviewers open the PNGs themselves before judging visual criteria.
